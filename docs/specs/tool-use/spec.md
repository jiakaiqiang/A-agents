# 工具系统与受限单轮闭环 Spec

## 背景

当前 MewCode TypeScript 客户端可以完成多轮文本对话，并已具备接收流式工具调用事件及
保存工具调用/结果历史的基础结构，但尚未向模型暴露可用工具，也不会执行模型请求的工具。

本次开发要将它升级为具备本地工作能力的终端 Agent：模型可根据用户请求选择一个文件或
命令类工具；MewCode 在当前项目工作目录内执行该工具，向用户展示工具过程与结果，并将
调用及结果保存到对话上下文。模型随后基于该结果生成本轮最终答复。

## 目标

- 提供统一的工具抽象；每个工具向模型暴露名称、描述和参数 Schema，并提供可执行的统一入口。
- 提供注册中心集中登记工具，支持按名称查找，并能导出当前 LLM 协议可识别的工具定义列表。
- 提供六项核心本地能力：读取文件、写入文件、唯一匹配替换文件内容、执行命令、按模式
  查找文件、搜索代码内容。
- 让 Anthropic、OpenAI 与 OpenAI 兼容协议都能收到同一套工具定义，并将流式工具调用
  转换为统一事件。
- 实现受限的单轮闭环：模型请求一个工具 → 本地执行 → 结果回灌 → 模型生成一次最终
  文本答复 → 停止。
- 最终答复阶段不允许再执行工具；若模型再次请求工具，给出明确的可见错误并结束该轮。
- 工具调用在 TUI 以 Claude Code 风格工具行呈现，例如 `● Read(path)`；完成后展示结果
  摘要，而完整结果保留在会话上下文中。
- 对工具参数错误、执行错误、超时、文件匹配失败等情况返回结构化结果，使模型能在最终
  答复中说明问题，而不会使应用崩溃。

## 功能需求

### 一、工具抽象与注册

- F1: 统一工具抽象
  系统提供单一的工具抽象，本期六个工具及后续新增工具均遵循同一形态。每个工具声明
  四项内容：(a) 名称，全局唯一，供模型在工具调用中引用；(b) 描述，面向模型，说明
  用途、适用时机与边界，使模型能在多个工具间正确选择；(c) 参数 Schema，可机器校验的
  结构化定义，包含每个参数的类型、是否必填与含义说明；(d) 执行入口，接收已校验的
  参数对象，执行本地操作并返回统一结果。工具的元信息与执行逻辑必须在同一处声明，
  避免二者不一致。

- F2: 统一工具结果结构
  所有工具执行返回同一结果结构，至少包含：(a) 是否成功，供编排层与 TUI 判断；
  (b) 面向模型的内容，写入会话历史、供模型续答使用的完整文本；(c) 面向用户的摘要，
  一行以内的简短结果描述，供 TUI 工具行展示；(d) 失败原因（失败时），可读的错误说明，
  必要时附带结构化细节（如匹配数量、退出码、越界路径）。任何工具在任何输入下都必须
  返回该结构，不得抛出未捕获异常。

- F3: 工具注册中心
  系统提供集中的工具注册中心，负责：启动时登记本期全部核心工具；按名称查找工具，
  未找到时返回明确的"未知工具"结果而非抛错；导出已登记工具的完整列表及其元信息，
  供系统提示词与协议定义生成使用。

- F4: 协议工具定义导出
  注册中心能将同一批工具转换为三种协议各自可识别的工具定义列表：Anthropic 协议格式、
  OpenAI Responses 协议格式、OpenAI 兼容（Chat Completions）协议格式。三份导出的
  工具名称、描述文本与参数语义必须完全一致，确保同一模型行为在不同 provider 下可复现。

### 二、六个核心工具

- F5: 读文件
  接收文件路径，以及可选的起始行偏移与最大行数，返回带行号的文件文本内容，便于模型
  在后续引用或修改时定位。文件不存在、路径指向目录、文件不可读、内容非文本或路径
  越界时，返回结构化错误结果。

- F6: 写文件
  接收文件路径与完整文件内容，以覆盖方式写入。目标文件不存在时创建；父目录不存在时
  自动创建。成功时返回文件路径与写入规模摘要；路径越界、目录创建失败或写入失败时
  返回结构化错误结果。

- F7: 改文件
  接收文件路径、原文片段、新文片段，以及可选的全量替换开关。默认模式要求原文片段在
  文件中恰好匹配一次，仅替换该处；匹配 0 次或多于 1 次时不修改文件，并返回包含实际
  匹配数的清晰错误，使模型能补充上下文后重试。开启全量替换后一次替换所有命中内容，
  并在结果中返回替换次数。文件不存在、路径越界或写回失败时返回结构化错误结果。

- F8: 执行命令
  接收 shell 命令，在当前工作目录下执行，受明确超时约束。结果包含标准输出、标准错误、
  退出码、是否超时，以及是否判定为执行错误。超时、无法启动进程与普通非零退出均以
  结构化结果返回，不中断会话。对以非零退出码表达业务语义的命令（例如"无匹配""存在
  差异"），不自动判定为工具错误，但完整保留原始退出码与输出供模型判断。

- F9: 按模式找文件
  接收 glob 文件模式，以及可选的搜索根目录，返回匹配文件的相对路径列表。搜索根目录
  必须位于工作目录内；自动忽略常见无关目录（版本控制目录、依赖目录、构建产物目录等）。
  结果按文件最近修改时间倒序排列，并受数量上限约束。无匹配时返回成功的空结果并给出
  说明；路径非法或搜索失败时返回结构化错误。

- F10: 搜代码内容
  接收搜索模式，以及可选的路径范围与文件名过滤条件，在符合条件的文件内容中检索。
  每条命中至少包含文件路径、行号与命中行内容。结果受数量上限约束；命中超过上限时
  返回已截取结果并明确标注截断。无命中、搜索模式非法或搜索过程失败时返回相应的
  结构化结果。

### 三、安全与资源边界

- F11: 工作目录边界
  六个工具均以 MewCode 启动时的当前工作目录为根。所有由模型提供的路径在实际操作前
  必须解析并校验，不得通过绝对路径、`..`、符号链接或等价路径形式访问根目录之外的
  位置。命令工具的工作目录同样固定为该根目录。越界访问一律以结构化错误拒绝，并在
  错误信息中说明原因。

- F12: 参数校验
  执行工具前，按其参数 Schema 校验模型给出的参数：必填缺失、类型不符或取值非法时不
  执行操作，直接返回可读的参数错误结果，使模型能在最终答复中说明或在后续轮次修正。

- F13: 结果体积约束
  单个工具结果写入会话历史前必须受体积上限约束。超过上限时进行截断，并在内容中明确
  标注被截断的事实与规模，避免单次工具输出挤占上下文或触发上下文超长错误。

### 四、协议层与流式解析

- F14: 流式工具调用解析
  三种协议的客户端在流式响应中识别工具调用的开始、参数增量与调用完成，将分片 JSON
  参数完整拼接后解析为统一的工具调用事件（含调用 ID、工具名、参数对象）。参数 JSON
  无法解析时，不得尝试执行不完整参数，而应生成该调用对应的结构化失败结果。

- F15: 会话历史中的工具消息
  会话历史需完整保存助手的工具调用与用户侧的工具结果，并在向各协议发送请求时正确
  还原为该协议要求的消息格式，保证工具调用与其结果通过调用 ID 严格配对。每个工具
  调用都必须有且仅有一条对应结果。

- F16: 工具信息进入系统提示词
  系统提示词需说明当前可用工具、其适用场景，以及本期的关键约束——每轮最多执行一个
  工具、工具操作限于当前工作目录，使模型的调用行为与实现能力一致。

### 五、单轮闭环编排

- F17: 受限单轮工具闭环
  每次用户提交后，系统向模型发送带工具定义的第一次请求。若模型请求工具：
  (1) 在 TUI 显示工具调用行；(2) 执行该工具；(3) 将助手的工具调用与对应工具结果
  写入会话历史；(4) 发起一次不携带工具定义的续答请求；(5) 流式呈现该次请求的最终
  文本答复，写入历史，结束本轮。若第一次请求未请求任何工具，则其文本即为本轮最终
  答复，不发起第二次请求。

- F18: 同次多个工具调用的处理
  若首次响应包含多个工具调用，仅执行第一个；其余每个调用均回灌"本期每轮仅支持一个
  工具调用"的结构化失败结果，确保调用与结果一一配对。随后照常进行一次无工具的最终
  续答请求，并在 TUI 中明确提示未执行的调用，不静默丢弃。

- F19: 最终续答阶段约束
  第二次请求不向模型提供任何工具定义。若模型仍以工具调用形式响应，系统不执行任何
  操作，在 TUI 与会话历史中记录"最终续答阶段不支持工具调用"的错误，并结束本轮。
  本期不存在第三次模型请求。

- F20: 中断处理
  用户可在首次请求、工具执行与续答请求任一阶段中断本轮。中断后：正在进行的模型流与
  命令执行应尽力终止；已完成的工具调用与结果保持配对写入历史；会话保持可用，用户可
  继续输入下一条消息。

- F21: 用量统计
  状态栏与用量显示需覆盖本轮两次模型请求，反映累计的输入、输出与缓存 token，而不是
  仅显示最后一次请求的数值。

### 六、终端呈现

- F22: Claude Code 风格工具行
  工具调用与结果以独立工具行呈现，不混入助手正文渲染。工具行在调用开始时出现，在
  执行完成后补上结果摘要，例如：

  ```text
  ● Read(src/llm/anthropic.ts)
  ● Edit(src/config.ts) — replaced 1 occurrence
  ● Bash(bun test) — exit 0
  ● Glob("**/*.tsx") — 12 files
  ● Grep("TODO") — 4 matches
  ```

- F23: 工具行内容规则
  工具行显示的是参数与结果的安全摘要：过长的参数值需截断，多行内容压缩为单行，不
  直接把完整工具输出作为聊天文本渲染。完整结果仅保留在会话上下文中供最终续答使用。

- F24: 失败的可见呈现
  工具失败时，工具行以可区分的样式与措辞展示失败摘要（如
  `● Edit(src/app.tsx) — failed: 3 matches, expected 1`），同时把结构化失败结果
  回灌给模型，使最终答复能解释问题并给出下一步建议。

## 非功能需求

- N1: 错误隔离
  工具执行的任何异常都不得冒泡到 TUI 或事件循环。文件系统错误、子进程错误、无效
  正则、编码错误、权限错误一律在工具边界内转为结构化失败结果。任何单个工具调用失败
  后，会话必须仍可继续输入下一条消息。

- N2: 响应性
  工具行需在收到工具调用完成事件时立即出现，不等待执行结束。工具执行与命令输出读取
  不得阻塞渲染或输入；长时间运行的命令期间，界面保持可中断状态。

- N3: 资源上限
  所有可能产生大量数据的操作都需有明确默认上限，并可在实现层集中配置：命令执行超时、
  命令输出体积、读文件行数与单行长度、glob 结果条数、grep 命中条数。上限触发时以
  截断加提示的方式呈现，而非报错或静默丢弃。

- N4: 安全边界
  路径边界校验在工具执行入口强制生效，不依赖模型自觉。命令工具不做任何隐式提权或
  参数改写。工具不向任何外部网络端点发送项目代码。

- N5: 密钥不回显
  工具链路的任何环节都不得输出密钥值。具体约束：
  (a) 工具行摘要、结果摘要、错误信息中不得包含密钥、令牌、私钥内容，涉及时仅以键名
  或路径指代；(b) 写入会话历史、发送给模型的工具结果中，命中密钥模式的内容替换为
  脱敏占位符；(c) 命令的标准输出与标准错误在进入界面和历史之前先经过脱敏，命令本身
  若含内联密钥（如 `--token=...`），工具行只显示脱敏后的命令；(d) 读文件工具对疑似
  凭据文件（`.env`、密钥文件、凭据存储）的内容同样脱敏后返回；(e) 任何调试日志、
  异常堆栈都不得携带密钥值。脱敏在工具边界统一处理，不允许各工具各写一套。

- N6: 跨平台一致性
  六个工具在 Windows、macOS、Linux 上行为一致：路径统一按 POSIX 风格对模型呈现，
  内部转换为平台路径；写文件保持原文件换行风格，新文件使用 `\n`；命令工具在各平台
  使用该平台的默认 shell。

- N7: 可扩展性
  新增第七个工具只需实现统一抽象并在注册中心登记一次，不需修改任何协议客户端、编排
  逻辑或 TUI 渲染代码。协议定义、系统提示词中的工具清单均由注册中心派生，不存在需要
  同步维护的第二份工具列表。

- N8: 协议一致性可验证
  同一组工具调用用例可在三种协议下运行并得到一致的工具执行结果，差异仅限于协议自身
  的消息格式。协议定义导出需可单独测试，无需真实网络请求。

- N9: 上下文效率
  工具结果进入历史前已完成截断与压缩，避免单次输出挤占上下文。工具消息的加入不得
  破坏既有的提示词缓存标记策略，也不得改变系统提示词的缓存位置。

- N10: 可测试性
  工具执行逻辑与 TUI、LLM 客户端解耦，可独立单元测试。文件类工具的测试在临时目录中
  进行，不污染仓库工作区，测试结束清理。测试通过 `bun test` 运行，类型检查通过
  `tsc --noEmit`。

- N11: 代码风格一致性
  新增代码遵循现有约定：TypeScript strict、`verbatimModuleSyntax`、相对导入带 `.js`
  扩展、中文行内注释、模块按 `src/<domain>/` 分层、错误类集中定义。不引入与现有依赖
  重复的第三方库。

- N12: 可观测性
  每个失败结果都能定位到具体原因类别（参数错误、越界、未找到、匹配数不符、超时、
  执行失败、未知工具、本期不支持），错误文本包含可操作信息（涉及的路径、匹配数、
  退出码），便于用户和模型判断下一步。

- N13: 向后兼容
  不改变现有纯文本对话的行为与呈现；模型不请求工具时，交互与当前完全一致。配置文件
  格式保持兼容，不新增必填字段。

## 不做的事

- Agent Loop：本期每轮最多两次模型请求、最多一次工具执行，不做自动多轮循环。
- 多工具连环调用与并行工具调用：同次响应的第二个及之后的调用不执行。
- 权限确认系统：本期工具在工作目录内直接执行，不做逐次授权确认。
- MCP 工具接入：不把 MCP server 暴露的工具纳入注册中心。
- 子 Agent / Task 类工具：不做工具内再起 Agent。
- 网络类工具：不做 WebFetch / WebSearch。
- Notebook 编辑、TodoWrite 等状态类工具。
- 工具结果的折叠/展开、翻页等交互；工具行只显示摘要。
- 工具调用的撤销与回滚：写文件与改文件不做备份或 undo。
- 上下文压缩：工具结果只做单条截断，不做历史摘要。
- 会话持久化：工具调用历史不落盘，重启后从空白开始。
- 扩展思考内容展示：思考增量仍接收但不渲染。

## 验收标准

### 工具抽象与注册

- AC1: (F1/F2) 六个工具均通过同一抽象定义，可分别取到名称、描述、参数 Schema 与
  执行入口；任意工具在空参数、类型错误、越界路径等输入下均返回统一结果结构，不抛出
  未捕获异常。
- AC2: (F3) 按名称查找已登记工具能取到实例；查找未登记名称返回 `unknown_tool`
  失败结果，不抛错。
- AC3: (F4/N8) 注册中心导出的 anthropic / openai / openai-compat 三份工具定义中，
  工具名称、描述文本、参数字段与必填项完全一致；该断言在无网络的单元测试中可执行。
- AC4: (N7) 新增一个测试工具并登记后，无需改动协议客户端、编排层与 TUI 代码即可
  被调用。

### 读文件

- AC5: (F5) 读取存在的文本文件返回带行号内容，行号与实际行号对应。
- AC6: (F5) 指定起始偏移与最大行数时仅返回该范围，并说明总行数或截断情况。
- AC7: (F5) 文件不存在、路径为目录、路径越界、内容非文本四种情况返回可区分的
  失败原因类别。
- AC8: (F5/N3) 文件超过默认行数上限时截断并标注，不返回全部内容。

### 写文件

- AC9: (F6) 写入不存在的文件成功创建；父目录不存在时自动创建后写入成功。
- AC10: (F6) 覆盖写入后文件内容与传入内容完全一致，成功结果含目标路径与写入规模。
