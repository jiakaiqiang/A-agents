# 上下文管理 Spec

## 背景

MewCode 的 Agent Loop 在一轮内反复「调模型 → 执行工具 → 结果回灌」，工具结果（文件读取、命令输出）是上下文 Token 的最大来源。当前只有单条工具结果 30K 字符的硬截断（`TOOL_RESULT_MAX_CHARS`），没有任何按 Token 预算管理对话历史的机制：对话累积足够多后，请求会撞上模型的上下文窗口上限，会话直接失败。

本模块为 MewCode 装上上下文管理能力：两层压缩策略——轻量预防（管单条消息大小）+ 重量兜底（管累积历史长度）——保证对话累积再多也不会因上下文溢出而瘫掉，让 MewCode 能在有限 Token 预算里长时间干活。

## 目标

- 单个超大的工具结果不再整体占用上下文：落盘存档，对话里只留预览与路径，需要时模型可重新读取。
- 单条消息内多个工具结果合计过大时，按大小从大到小依次存盘，直到该消息回到预算内。
- 累积历史逼近窗口上限时，自动调用 LLM 生成结构化摘要，把较早的消息摘要化、近期原文保留，会话不中断。
- 用户可手动触发压缩；摘要连续失败时熔断自动压缩，避免死循环。
- Token 用近似估算，不实现精确 tokenizer。

## 功能需求

### Token 估算

- **F1**：提供会话级 Token 估算器：以最近一次 API 响应的 usage（input tokens）为锚点基数，之后仅对历史增量部分按字符数近似估算（统一按约 4 字符 ≈ 1 token 折算）；无锚点时全部按字符估算。估算器对所有协议（anthropic / openai / openai-compat）一致适用。

### 轻量预防（第一层）

- **F2**：工具结果在写入对话之前处理：单条工具结果的 Token 估算超过单条阈值（默认 2K tokens）时，该结果整体存盘，对话内只保留「开头约 500 字符预览 + 存盘文件路径」。
- **F3**：同一条消息的工具结果合计 Token 估算超过单条消息合计阈值（默认 8K tokens）时，从最大的结果开始依次存盘（每条存盘同样替换为预览+路径），直到合计回到阈值以内。
- **F4**：存盘文件写入项目内目录 `<工作目录>/.mewcode/tool-outputs/`，文件名为「工具名-时间戳-短随机串.txt」；存盘文件包含完整的原始结果内容。`.mewcode/tool-outputs/` 加入 `.gitignore`。
- **F5**：存盘后的预览文本含两部分：结果开头约 500 字符的原文、一行存盘路径提示（供模型用 Read 重新读取）。存盘动作不打断工具行的事件流展示。

### 重量兜底（第二层）

- **F6**：每次 API 请求前（含同一轮内工具回灌后的每次请求），先跑轻量预防（仅对刚产出、尚未入史的工具结果），再做整体检查：估算总 Token 超过「窗口 − 13K 安全余量」时触发自动压缩。安全余量为 13K 以防估算误差。
- **F7**：压缩时把历史划分为「待摘要区」与「近期原文区」：从尾部按 Token 往回数，累计达到约 10K tokens 或已包含至少 5 条自然语言消息（用户输入、助手回复；工具结果消息不占名额但 Token 照算）即停，先触发的条件生效。近期原文区之前的所有消息进入待摘要区。
- **F8**：调用当前会话的 LLM 生成结构化摘要，摘要按固定九个部分组织：①主要请求和意图 ②关键技术概念 ③文件和代码段 ④错误和修复 ⑤问题解决过程 ⑥所有用户消息 ⑦待办任务 ⑧当前工作 ⑨可能的下一步。
- **F9**：摘要请求的 Prompt 明确要求模型不得调用任何工具；并要求先写分析草稿再写正式摘要，草稿不进入任何持久化输出，用完即弃。
- **F10**：待摘要区非常大时，摘要请求发出前把待摘要区临时截短到安全大小（从尾部保留 5 轮原始对话，其余部分截短压缩），保证请求能发出；压缩完成后一次性替换历史。
- **F11**：压缩后的新历史 = 一条承载摘要的 user 消息 + 近期原文区消息 + 一条 user 角色的边界消息（提示模型：文件细节请用 Read 重新读取，不要根据摘要臆测代码）。摘要消息与边界消息均写入会话历史。
- **F12**：压缩完成后，Token 估算锚点重置（按压缩后历史重新估算），保证后续判断基于新基线。

### 触发与熔断

- **F13**：用户在 TUI 输入 `/compact` 手动触发压缩，不设阈值，调用即压；压缩完成后若剩余空间仍不足 3K tokens，向用户提示异常。手动触发不经过 13K 余量线。
- **F14**：摘要请求连续失败 3 次后熔断自动压缩：此后不再自动触发，请求按原样发出（风险自负），并向用户提示「压缩连续失败，已暂停自动压缩」。熔断计数仅在手动 `/compact` 成功一次后重置，自动压缩恢复。

### 用户反馈

- **F15**：压缩发生时（自动或手动）在 TUI 显示一条系统提示，说明压缩了哪些内容（如「已压缩历史：X 条消息 → 摘要 + 近期 Y 条原文」）。

## 非功能需求

- **N1**：上下文管理模块是纯逻辑层，不依赖 TUI/React；TUI 通过事件与返回值消费。
- **N2**：不引入新依赖；存盘用 Node/Bun 标准库（`node:fs`）。
- **N3**：压缩过程可被用户的 AbortSignal 中断；中断时不替换历史，会话保持原样可用。
- **N4**：所有阈值常量集中在 limits 处集中管理，可统一调整。
- **N5**：用户的原始消息尽量原文保留：摘要只作用于待摘要区，且轻量预防不触碰自然语言消息。
- **N6**：测试不依赖真实 LLM——摘要生成器通过注入的假客户端测试。

## 不做的事

- 精确 tokenizer（字符近似估算已满足需求）
- 摘要策略的机器学习优化
- 可配置独立摘要模型（一律用主模型）
- 存盘文件的自动清理/过期机制
- 压缩后的缓存前缀优化（缓存断裂可接受）
- `/compact` 之外的压缩管理命令（如查看存盘列表）
- 跨会话的存盘索引

## 验收标准

- **AC1**（F1）：有 usage 锚点时，估算值 = 锚点 + 增量字符/4；无锚点时全部按字符/4 估算。
- **AC2**（F2）：单条工具结果估算超过 2K tokens 时，历史中该结果被替换为「~500 字符预览 + 存盘路径」，存盘文件内容为完整原文。
- **AC3**（F3）：一条消息多条结果合计超 8K tokens 时，从最大的开始依次替换，直到合计回到 8K 以内。
- **AC4**（F4）：存盘文件出现在 `<工作目录>/.mewcode/tool-outputs/`，文件名含工具名与时间戳，内容完整；`.gitignore` 已包含该目录。
- **AC5**（F5）：预览文本包含开头原文与路径提示；工具行展示流程不受影响。
- **AC6**（F6）：每次请求前执行两层检查；总估算超过「窗口−13K」时自动触发压缩；未超过时不触发。
- **AC7**（F7）：分界满足「尾部 ~10K tokens 或 ≥5 条自然语言消息取先到」；自然语言消息计数不含工具结果消息。
- **AC8**（F8/F9）：摘要 Prompt 含九段结构要求、禁用工具声明与草稿要求；假客户端能收到该 Prompt。
- **AC9**（F10）：待摘要区超大时请求发出前被截短到安全大小，压缩完成后历史一次性替换。
- **AC10**（F11）：压缩后历史开头是摘要 user 消息，尾部追加边界消息，中间是近期原文；原始近期消息内容不变。
- **AC11**（F12）：压缩完成后估算锚点按新历史重置。
- **AC12**（F13）：`/compact` 无阈值直接压缩；压后剩余 <3K tokens 时出现异常提示。
- **AC13**（F14）：摘要连续失败 3 次后，自动压缩停止且用户收到熔断提示；手动 /compact 成功后熔断解除。
- **AC14**（F15）：压缩发生时 TUI 出现含消息条数的系统提示。
- **AC15**（N3）：压缩过程中收到中断信号时历史不被替换，会话可继续正常使用。
