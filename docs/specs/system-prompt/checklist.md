# System Prompt Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为而非代码结构。
> 工作目录 `typescript/`，除注明「人工」的条目外均可用命令验证。
>
> 验收记录（2026-09-09）：`bun run typecheck` 退出码 0；`bun test` 149 pass / 0 fail /
> 452 expect() calls / 18 files。基线为 72 pass，新增 77 条断言。
> 标 `[x]` 的是本次已验证；标 `[ ]` 的是需要真实 API 或人工在 tmux 中观察，尚未进行。

## 系统提示词模块化

- [x] 七个固定模块全部出现在稳定段中，顺序为身份 → 安全边界 → 任务模式 → 行为 →
      代码规范 → 工具使用 → 输出风格（验证：`bun test tests/prompt/builder.test.ts`，
      顺序断言通过）
- [x] 模块之间以恰好一个空行分隔，不出现连续空行（验证：同上，空行断言通过）
- [x] 新增一个优先级居中的模块时，它出现在预期位置且组装逻辑未改动（验证：同上，
      临时 Section 断言通过）
- [x] 每个模块的内容不再是单行占位，可对应到各自职责（验证：通读 `sections.ts`
      七个模块，每个 4–8 条具体约定，对照 spec F2 的七项职责逐条核过）
- [x] 三个可选模块内容为空或纯空白时，稳定段中不出现对应内容与多余空行（验证：同上，
      空可选模块断言通过）
- [x] 三个可选模块提供内容时，出现在七个固定模块之后（验证：同上，位置断言通过）
- [x] 环境段包含工作目录、操作系统与架构、Shell、Git 状态与分支、模型、日期六项
      （验证：同上，环境段字段断言通过）
- [x] 在非 Git 目录下构造提示词不报错，Git 一项有明确取值（验证：同上，
      `detectEnvironment("/")` 断言 `isGitRepo` 为布尔值且无异常）

## 缓存分层

- [x] Anthropic 请求的系统内容以两块发出，两块各自带缓存标记（验证：
      `bun test tests/llm/messages.test.ts`，system 数组长度与标记断言通过）
- [x] 第一块内容等于稳定段，第二块等于环境段（验证：同上）
- [x] 同一入参连续两次构造，稳定段字符串严格相等（验证：
      `bun test tests/prompt/builder.test.ts`，逐字节稳定断言通过）
- [x] 稳定段中不含日期、分支、轮次计数、已用 token 数等随时间或轮次变化的内容
      （验证：同上，稳定段不含 date/model 断言通过；轮次计数与 token 数由
      `ModeTracker` 和 usage 事件承载，不进提示词）
- [x] 同一模式下连续两次构造工具定义序列，序列化结果完全相等（验证：现有
      `bun test tests/tools/registry.test.ts` 通过，该文件已覆盖三协议一致性）
- [x] 切换模式前后稳定段内容完全相等（验证：`bun test tests/prompt/builder.test.ts`，
      模式无关断言通过——`buildSystemPrompt` 已不接受模式参数）
- [ ] 切换模式不触发客户端重建（验证：人工在 tmux 中切模式，观察不出现「正在初始化
      LLM 客户端」提示、切换后首条消息即可发出）
      —— 代码侧已就位：`app.tsx:116` 的 useEffect 依赖数组已去掉 `mode`；行为待人工确认
- [x] 仅环境信息变化时稳定段不变（验证：同上，传入不同日期、分支、模型后
      断言稳定段逐字节相等、环境段不同）

## 运行期指令注入

- [x] 注入的补充指令以 `<system-reminder>` 成对标签包裹（验证：
      `bun test tests/prompt/reminder.test.ts`，标签断言通过）
- [x] 末条为纯文本用户消息时，补充指令追加进该消息且原文本保留（验证：
      `bun test tests/llm/messages.test.ts`）
- [x] 末条为工具结果消息时，补充指令作为文本块追加在工具结果之后（验证：同上，
      同时断言相邻消息角色不重复）
- [x] 三种协议构造出的请求中都能找到补充指令内容（验证：同上，三协议断言通过）
- [x] 连续三轮注入后会话历史中不含任何补充指令内容（验证：同上，不进历史断言通过）
- [x] 第二轮的请求中不包含第一轮注入的内容（验证：同上）
- [x] 注入内容变化时两段内容与两个缓存标记位置均不变（验证：同上，
      `buildSystemBlocks` 在挂载 reminders 前后结果相等断言通过）
- [ ] 模型不针对补充指令内容本身作答（验证：人工——在 tmux 中切到计划模式发一条
      普通请求，观察回复是在回应请求本身，而不是在解释或确认「我处于计划模式」）

## 模式指令按轮次注入

- [x] 计划模式第 1 轮与第 6 轮注入完整版，第 2 至第 5 轮注入精简版（验证：
      `bun test tests/prompt/reminder.test.ts`，六轮规律断言通过）
- [x] 把间隔轮数改为其他值时该规律随之变化（验证：同上，断言直接由
      `PLAN_REMINDER_INTERVAL` 推导，完整版轮次为 `[0, N]`，非硬编码 `[0, 5]`）
- [x] 从执行模式切入计划模式后的第一轮为完整版（验证：同上）
- [x] 计划模式跑若干轮后切回执行再切回计划，计数归零、首轮为完整版（验证：同上）
- [x] 执行模式下不注入模式指令（验证：同上，返回空数组断言通过）
- [x] 稳定段中不含「当前处于计划模式」这类声明（验证：
      `bun test tests/prompt/builder.test.ts`，断言不含「当前处于计划模式」
      与「当前处于执行模式」。注：任务模式一节仍解释两种模式的差别，这是静态说明，
      不是当前状态声明，所以按状态短语而非「计划模式」字样断言）
- [x] 工具使用模块中不含计划模式的行为约束（验证：同上，切出工具使用一节后
      断言不含「计划模式」与「批准」）

## 双重强化

- [x] 写入类与编辑类工具的描述中含「先用 Read 确认当前内容」的约定（验证：
      `write.ts:41`「写入已存在的文件前必须先用 Read 确认当前内容」、
      `edit.ts:78`「编辑前必须先用 Read 确认当前内容」）
- [x] 查找与搜索类工具的描述中含「优先使用本工具而不是命令行」的约定（验证：
      `glob.ts:52`「查找文件用本工具，不要用 Bash 拼 find、ls」、
      `grep.ts:115`「搜索内容用本工具，不要用 Bash 拼 grep、rg」；
      `bash.ts:147` 反向重申一遍分工）
- [x] 涉及路径的工具描述中含相对路径约定（验证：Read、Write、Edit、Glob 四处均含
      「相对于工作目录的相对路径」）
- [x] 系统提示词中能找到与上述同一批规则的重申（验证：`sections.ts:111-113`
      工具使用一节三条；`sections.ts:69` 行为一节「动手前先读相关文件与已有约定」）
- [x] 工具描述与系统提示词对同一规则的表述一致，不存在一处要求、另一处放宽（验证：
      三条规则逐字比对——「编辑或写入文件前必须先用 Read 确认当前内容」、
      「查找文件用 Glob、搜索内容用 Grep，不要用命令行拼凑」、
      「文件路径使用相对于工作目录的相对路径」，两处均为强制措辞）

- [x] 执行模式下第一个缓存单元覆盖的前缀长度超过门槛（验证：
      `bun test tests/prompt/builder.test.ts`，token 估算断言通过。
      实测稳定段约 1587 token，已超 1024）
- [x] 计划模式下第一个缓存单元覆盖的前缀长度同样超过门槛（验证：同上。
      稳定段不随模式变化，1587 token 即为最短情形，工具定义还在其前）
- [x] 门槛值有记录且注明适用模型（验证：`src/tools/limits.ts:46` 注释
      「Opus/Sonnet 为 1024，Haiku 为 2048」）

- [x] 模块优先级、注入间隔轮数、长度门槛均在单一位置声明（验证：三者都在
      `src/tools/limits.ts:29/44/48`，`grep` 确认其他文件无重复定义）
