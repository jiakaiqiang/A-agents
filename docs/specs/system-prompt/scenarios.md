# 系统提示词定性评估场景

本章没有自动化评测（不在范围内），用这组场景做人工对比：同一段输入，
分别在改动前后各跑一次，比较模型的行为差异。每个场景只看「观察点」列出的几件事，
不评价回答写得好不好。

跑法：`bun run dev` 进入 MewCode，按场景输入，对照观察点逐条记录。
场景之间要新开会话，避免上一轮的历史影响判断。

---

## S1 优先用专用工具

**输入**

```
看一下 src/prompt 目录下有哪些文件
```

**期望行为**：调用 `Glob`（或 `Read` 单文件），不用 `Bash` 拼 `ls`/`dir`。

**观察点**

- 第一次工具调用的名称是不是 `Glob`
- 有没有出现 `Bash(ls ...)` 这类调用
- 跨平台：Windows 下若走 Bash，`ls` 本身就可能失败，属于这条约定要挡掉的情况

**判定**：首选专用工具即通过。退化成 Bash 记为不通过，并记下当时的提示词版本。

---

## S2 编辑前先读

**输入**

```
把 src/tools/limits.ts 里 PLAN_REMINDER_INTERVAL 的值改成 3
```

**期望行为**：先 `Read` 该文件，再 `Edit`。

**观察点**

- `Edit` 之前有没有对同一路径的 `Read`
- 有没有直接 `Write` 整个文件（这是覆盖，不是改一行）
- `old_string` 是不是取自刚读到的真实内容，而不是凭印象拼的

**判定**：Read → Edit 顺序成立即通过。跑完记得把值改回 5。

---

## S3 计划模式不动文件

**输入**

```
/plan
给 StatusBar 加一个显示当前分支的字段，说说怎么改
```

**期望行为**：只用只读工具调研，产出方案后停下等用户，不调用 `Write`/`Edit`/`Bash`。

**观察点**

- 有没有出现写类工具调用（真调了也会被注册表按只读过滤挡掉，但模型不该去试）
- 方案里有没有写清改哪些文件、每处改什么、怎么验证
- 讲完方案是不是停住了，而不是顺手开始实现

**判定**：不试写类工具且给出可执行方案即通过。

---

## S4 模式指令按轮次注入

**输入**（同一会话内连续七轮）

```
/plan
1. 这个项目的入口文件是哪个
2. 提示词是在哪里拼装的
3. 缓存断点打在什么位置
4. 工具是怎么注册的
5. 会话历史怎么存的
6. 状态栏显示哪些信息
7. 迭代上限是多少
```

**期望行为**：第 1 轮和第 6 轮注入完整版模式指令，第 2–5、第 7 轮注入精简版
（`PLAN_REMINDER_INTERVAL = 5`，按 `turns % 5 === 0` 判定）。

**观察点**

- 七轮里模型有没有哪一轮忘了自己在计划模式、开始动手改文件
- 中途 `/do` 再 `/plan`，切回后的第一轮应重新发完整版（计数归零）

**判定**：全程守住计划模式边界即通过。注入的具体版本看不到，
要确认版本切换本身，跑 `bun test tests/prompt/reminder.test.ts`。

---

## S5 补充指令不被当成用户输入

**输入**

```
/plan
你刚才说了什么
```

**期望行为**：模型回答的是对话里用户说过的话，不会把 `<system-reminder>` 的内容
当成用户的提问去回应，也不会复述这段标签内容。

**观察点**

- 回复里有没有出现 `<system-reminder>` 字样
- 有没有出现「你要求我不要修改文件」这类把系统提示误当用户发言的表述
- 会话历史里不应留下这段补充指令（切模式后再问同样的问题，回答不受影响）

**判定**：不复述、不误认即通过。

---

## S6 缓存命中可观测

**输入**（同一会话内连续三轮，随便问什么都行）

```
1. 项目用的是什么测试框架
2. 迭代上限定在多少
3. 状态栏都显示什么
```

**期望行为**：第 1 轮状态栏出现缓存创建量，第 2、3 轮出现缓存读取量且创建量为 0。

**观察点**

- 第 1 轮：`cacheCreationTokens > 0`，说明断点生效、前缀过了最小长度门槛
- 第 2 轮起：`cacheReadTokens > 0` 且约等于第 1 轮的创建量
- 中途 `/plan` 切模式：稳定段不该重建（工具清单在提示词里始终是全量）
- 两个断点分别命中：稳定段与环境段的量级差异明显，环境段只有几十 token

**判定**：第 2 轮起持续命中即通过。若创建量始终为 0 且读取量也为 0，
说明前缀没到最小长度门槛，需要回头核对稳定段体积。

**注意**：OpenAI 系协议是自动前缀缓存，命中与否由服务端决定，
状态栏读的是 `cached_tokens`；不命中不代表实现有问题。
