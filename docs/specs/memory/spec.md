# 记忆系统 Spec

> 实现状态（2026-10-19）：F1–F14 已接入 TypeScript 版 MewCode；全量测试 373 pass / 0 fail，类型检查通过。真实 provider 验证通过，tmux 手工场景的环境限制与替代验证见 `checklist.md`。

## 背景

MewCode 每次启动都是一张白纸：项目技术栈、代码规范、用户偏好、上次被纠正过的错误，每个新会话都要重新交代。会话只存在内存里，进程退出或崩溃后进行中的工作无法接续。

现有基础：系统提示词已为「自定义指令」与「记忆」预留位置但始终为空；对话管理器有长期记忆注入的空桩；上下文压缩能力已就绪可复用；`.mewcode/` 目录约定已用于配置与工具输出存盘。

## 目标

- 新会话启动时自动加载项目指令与长期记忆，Agent 在处理第一个请求前就已「读过」项目规矩与用户偏好。
- 会话持续落盘，进程中断后可通过 `/resume` 从断点接着用。
- Agent 在使用中自动积累四类笔记（用户偏好、纠正反馈、项目知识、参考资料），越用越懂用户。
- 工作记忆（会话存档）与长期记忆（指令文件、笔记）分层管理，用户级与项目级分开存放。
- 不做向量检索：记忆以索引形式整体注入，体量控制在约 2-3K tokens。

## 功能需求

### 一、项目指令文件

- **F1**：会话启动时从三处读取 `MEWCODE.md`：`项目根/`、`项目根/.mewcode/`、`~/.mewcode/`，按此顺序（优先级从高到低）拼接，每段标注来源；系统提示词中说明「冲突时以排在前面的为准」。缺失的文件跳过；三处都没有时不生成该段。
- **F2**：一行内容仅为 `@路径`、且路径形似文件地址（以 `./`、`../`、`~/` 开头，或含 `/`，或带文件扩展名）时，视为引用，读取时把被引用文件内容展开到该行位置。`@Override`、`@Test` 这类 `@` 后只跟一个单词的行按普通文本原样保留，不展开也不告警；Markdown 代码块内的 `@` 行一律不展开。规则：
  - 相对路径以当前文件所在目录为基准；
  - 最多嵌套 5 层；
  - 同一次加载中已展开过的文件不再展开（同时防环路与重复）；
  - 项目级文件只能引用项目目录内的文件，用户级文件只能引用 `~/.mewcode/` 内的文件；
  - 越界、超深度、重复、文件不存在时跳过该行并产生一条告警，启动时在 TUI 呈现，不阻断启动。
- **F3**：指令内容在会话启动时加载一次，放入系统提示词稳定段；会话中途修改文件，下个会话才生效。

### 二、会话存档与恢复

- **F4**：每个会话的 ID 格式为 `YYYYMMDD-HHMMSS-xxxx`（`xxxx` 为 4 位随机串），对应文件 `<项目>/.mewcode/sessions/<ID>.jsonl`。文件在第一条消息写入时才创建，不留空会话文件。`.mewcode/sessions/` 加入 `.gitignore`。
- **F5**：每有一条消息进入对话历史，同步向文件追加一行记录（时间戳 + 完整消息：用户输入、助手回复、思考块、工具调用、工具结果、系统提醒）。发生压缩时追加一条压缩记录，内含压缩后的完整新历史。文件只追加、不改写。
- **F6**：不维护单独的元数据文件。会话列表扫描 sessions 目录现算：ID（文件名）、标题（第一条用户消息前 50 字符）、消息数、最后活跃时间（最后一条有效记录的时间戳）。按最后活跃时间倒序，排除当前会话。
- **F7**：TUI 输入 `/resume` 列出最近 20 个会话供选择，Esc 取消；没有可恢复会话时提示「暂无历史会话」。Agent 运行中输入框保持可输入，但只接受 `/resume`：
  - 运行中提交 `/resume` 且有可恢复会话时，先按「用户取消」中断本轮（与按 Esc 一致：历史补收尾、不触发记忆更新），收尾完成后弹出会话列表；没有可恢复会话时只提示「暂无历史会话」，不中断本轮；
  - 运行中提交其他内容时提示「Agent 运行中，仅支持 /resume；可按 Esc 中断」，已输入内容保留在输入框中；
  - 权限确认框弹出期间输入框不显示（维持现状），需先处理确认框。

  选中会话后：
  - 当前对话历史替换为恢复出的历史；
  - 聊天区显示恢复出的用户消息与助手文本回复，工具调用不重新展示；
  - 显示系统提示「已恢复会话 xxx：N 条消息」；
  - 之后的新消息继续追加到原会话文件。
- **F8**：重建历史 = 最后一条压缩记录的历史 + 其后的所有消息记录（无压缩记录则从头开始）。重建时处理四类异常：
  - 坏行：无法解析或结构不合法的行跳过，跳过行数写入恢复提示；
  - 工具调用不配对：某条助手消息的工具调用未在紧随其后的消息中拿到全部结果时，从该助手消息起截断，之后全部丢弃；
  - Token 超限：重建后估算超过自动压缩线时，先压缩一次再载入；压缩失败照常载入并提示，后续由现有自动压缩机制接管；
  - 时间跨度：最后一条记录距今超过 4 小时，向历史追加一条系统提醒（「距上次对话已过去 X，期间文件可能已变化，涉及文件内容时请重新读取」），该提醒同样写入会话文件。
- **F9**：每次启动时清理当前项目 sessions 目录下最后修改时间超过 30 天的会话文件；删除失败忽略，不影响启动。

### 三、自动笔记

- **F10**：笔记分两处存放，结构相同：用户级 `~/.mewcode/memory/`，项目级 `<项目>/.mewcode/memory/`。每条笔记一个 Markdown 文件，frontmatter 含名称、一句话描述、类型（用户偏好 / 纠正反馈 / 项目知识 / 参考资料）。每处有一个索引文件 `MEMORY.md`，每条笔记一行，该行本身是一条完整的短事实并附文件名。
- **F11**：会话启动时读取两份索引，以「用户级记忆 / 项目级记忆」分段放入系统提示词记忆段。单份索引超过 200 行或 25KB 时截断到上限并标注「已截断」。
- **F12**：一轮 Agent Loop 自然完成（模型最终回复无工具调用）后，后台异步发起一次记忆更新，不阻塞用户继续输入。用户取消、出错、达到迭代上限时不触发。多次更新串行执行，不并发。
- **F13**：更新请求使用当前会话主模型，禁止调用工具。输入：本轮用户消息与助手文本回复（工具调用只列工具名，不带结果）、两份现有索引及其当前行数与体积。Prompt 要求：
  - 按四类判断哪些内容值得长期记住；用户偏好、纠正反馈默认写用户级，项目知识、参考资料默认写项目级；
  - 与已有笔记重复的合并或更新，不重复新增；过时或错误的删除；
  - 不记录密钥、密码、令牌等敏感值；
  - 索引超限时合并、精简条目；
  - 没有值得记的内容返回「无变更」。

  模型返回一组结构化操作（新增 / 更新 / 删除，每个带归属范围与笔记内容），系统执行并同步重写对应索引。
- **F14**：更新成功且有实际变更时，TUI 显示一行淡色提示「已更新记忆：<笔记名列表>」。更新失败或模型输出不合法时不提示、不重试，会话照常。进程退出时不等待进行中的更新。

### 四、并发保护

- **F15**：会话独占。一个会话同一时刻只能被一个 MewCode 进程写入：新建会话即占用，`/resume` 切换时先占用目标会话再释放当前会话，进程退出时释放。持有进程已不存在的占用视为残留，自动失效。`/resume` 列表中被其他存活进程占用的会话标注「使用中」，选中时提示「该会话正在被另一个 MewCode 使用」且不恢复；过期清理跳过被占用的会话。
- **F16**：记忆写入互斥与冲突检测。执行笔记操作与重写索引期间，对所写范围（用户级 / 项目级）持有跨进程互斥；调用 LLM 期间不持有。需要同时写两个范围时固定按「先用户级、后项目级」的顺序获取。发起更新时记下两个范围的内容指纹，写入前（持有互斥时）重新计算，发现已被其他实例修改则放弃本批操作、用最新索引重新发起一次更新（只重试一次，仍冲突则放弃）。等待互斥超时同样放弃，均按 F14 静默处理。持有进程已不存在、或持有时间超过上限的互斥视为残留，自动失效。
- **F17**：占用与互斥的标记文件存放在 `.mewcode/locks/`（项目级）与 `~/.mewcode/locks/`（用户级），`.mewcode/locks/` 加入 `.gitignore`；临时文件名含随机串且独占创建，两个进程不会写同一个临时文件。

## 非功能需求

- **N1**：三套机制均为纯逻辑层，不依赖 TUI；TUI 通过返回值与事件消费。
- **N2**：不引入新依赖。
- **N3**：会话写盘每条消息只追加一行；进程崩溃最多丢失正在写的那一行，之前的记录完整可读。
- **N4**：笔记与索引文件采用「写临时文件再重命名」，崩溃不会留下写了一半的文件。
- **N5**：任何一套机制失败（文件不可读、目录不可写、LLM 出错）都不阻断启动与对话，只降级并按需提示。
- **N6**：所有阈值集中一处声明：嵌套 5 层、索引 200 行 / 25KB、时间提醒 4 小时、过期 30 天、列表 20 条、标题 50 字符、记忆互斥等待 2 秒、记忆互斥残留判定 30 秒。
- **N7**：指令与记忆在启动时加载一次，放在系统提示词稳定段，会话期间字节不变，不破坏 Prompt 缓存。
- **N8**：路径越界判断穿透符号链接，与现有工具的越界判定口径一致。
- **N9**：测试不依赖真实 LLM，后台更新用注入的假客户端；文件系统测试使用临时目录，不触碰真实 `~/.mewcode/`（用户目录可注入）。
- **N10**：会话文件含完整工具输出，可能带敏感信息，已加入 `.gitignore`；项目级笔记默认进 git，更新 Prompt 明确禁止记录敏感值。

## 不做的事

- 向量数据库、RAG 检索、团队记忆同步
- 查看 / 编辑 / 删除记忆的命令（如 `/memory`），用户可直接手改文件
- 会话的删除、重命名、导出命令，以及跨项目列出会话
- 启动参数形式的恢复（`--continue`、`--resume <ID>`）
- 用 LLM 生成会话标题
- 本会话新写的笔记在本会话内即时生效；指令文件热重载
- 恢复时另开新会话（fork）
- Agent 运行中输入普通消息排队到下一轮（后续支持）；运行中除 `/resume` 外的其他斜杠命令
- 后台记忆更新的失败重试
- 工具输出存盘目录的清理（沿用上下文管理 spec 的决定）

## 验收标准

- **AC1**（F1）：三处 `MEWCODE.md` 都存在时，系统提示词按「项目根 → 项目根/.mewcode → 用户级」顺序包含三段内容，各带来源标注与冲突说明；删掉其中一份，对应段消失；三份都没有时提示词中无该段。
- **AC2**（F2）：`@docs/a.md` 被展开为文件内容；`@Override` 原样保留且无告警；代码块内的 `@docs/a.md` 不展开；A 引用 B、B 引用 A 时各展开一次并产生环路告警；6 层引用链的第 6 层不展开并告警；项目级文件中 `@../outside.md` 被拦截并告警；用户级文件引用 `~/.mewcode/` 之外的文件被拦截并告警；引用不存在的文件告警；以上情况启动均不被阻断。
- **AC3**（F3）：会话中修改 `MEWCODE.md`，本会话后续请求的系统提示词不变；新会话中能看到修改。
- **AC4**（F4）：会话 ID 符合 `YYYYMMDD-HHMMSS-xxxx`；同一秒内创建的两个会话 ID 不同；发出第一条消息前 sessions 目录下不存在该会话文件；`.gitignore` 已包含 `.mewcode/sessions/`。
- **AC5**（F5）：一轮含工具调用的对话后，会话文件中每条历史消息对应一行带时间戳的合法 JSON（含思考块、工具调用与结果）；压缩后文件末尾多一条压缩记录，此前各行内容不变。
- **AC6**（F6）：会话列表的 ID、标题、消息数、最后活跃时间与 JSONL 内容一致，按最后活跃时间倒序且不含当前会话；sessions 目录下没有任何元数据文件；含坏行的会话仍能列出，消息数只计有效行。
- **AC7**（F7）：`/resume` 最多列 20 条；Esc 取消后对话不变；无历史时提示「暂无历史会话」；Agent 运行中提交 `/resume` 时本轮被中断（出现「本轮已中断」）且随后弹出列表、该轮不触发记忆更新，无历史会话时只提示且本轮继续；运行中提交其他内容时出现「仅支持 /resume」提示且输入框内容保留；选中后聊天区出现历史用户消息与助手回复及「已恢复会话」提示，追问早先内容时模型能正确回答，新消息追加到原会话文件。
- **AC8**（F8）：坏行被跳过且跳过行数出现在恢复提示中；末尾工具调用缺结果时从该助手消息起被截断；有压缩记录时历史从最后一条压缩记录重建；重建后超过自动压缩线时先压缩再载入（假客户端收到摘要请求）；压缩失败时仍载入并提示；最后记录距今超过 4 小时时历史末尾出现时间跨度提醒且该提醒写入文件，未超过 4 小时则无提醒。
- **AC9**（F9）：启动后最后修改时间 31 天前的会话文件被删除，29 天前的保留；删除失败时启动正常。
- **AC10**（F10）：后台更新写入的笔记文件 frontmatter 含名称、描述、类型（四类之一），存放在对应范围的目录；对应 `MEMORY.md` 每条笔记一行。
- **AC11**（F11）：系统提示词包含分段标注的用户级与项目级索引；250 行的索引被截断到 200 行并标注「已截断」；超过 25KB 的索引被截断到 25KB 以内。
- **AC12**（F12）：自然完成的一轮触发一次更新；取消、出错、达到迭代上限的轮次不触发；更新进行中用户可正常输入；连续两轮快速完成时，第二次更新在第一次结束后才开始。
- **AC13**（F13）：假客户端收到的请求不含工具定义，内容含本轮用户与助手文本、工具名（不含工具结果）、两份索引及其行数与体积、四类规则 / 去重 / 禁敏感值 / 超限精简 / 无变更要求；返回的新增、更新、删除操作被正确执行且索引同步重写；返回「无变更」时文件无任何变化；返回对已有笔记的更新时不产生新文件。
- **AC14**（F14）：有变更时 TUI 出现「已更新记忆：…」淡色提示；更新失败或输出不合法时无提示、会话可继续；更新进行中执行 `/exit` 立即退出。
- **AC15**（N3/N4）：会话文件最后一行被截断（模拟崩溃）时，恢复跳过该行、其余消息完整；笔记写入过程中不出现半截文件。
- **AC16**（N5）：sessions 目录不可写时，对话仍可正常进行，并给出一次提示；memory 目录不可写时，对话仍可正常进行且不提示（与 F14 一致）。
- **AC17**（N7）：同一会话内，即使后台写入了新笔记，每次请求的系统提示词字节完全一致。
- **AC18**（F15/F17）：两个 MewCode 进程同时运行时，A 的当前会话在 B 的 `/resume` 列表中标注「使用中」，B 选中后提示被占用且历史不变；A 退出后 B 可正常恢复该会话；A 被强杀后残留的占用不妨碍 B 恢复；被占用的会话即使超过 30 天也不被清理；`git check-ignore` 命中 `.mewcode/locks/` 下的文件。
- **AC19**（F16/F17）：写入阶段持有互斥时另一实例的写入等待或超时放弃，不出现半截文件或残留临时文件；发起更新后、写入前笔记目录被另一实例修改时，本批操作不落盘且以最新索引重新发起一次更新（假客户端收到第二次请求，内含新索引）；第二次仍冲突则放弃且无写入；残留的互斥（持有进程已不存在或超过 30 秒）不阻塞写入。
