## 端到端场景（tmux，真实 provider）

- [ ] 场景 1：指令与记忆跨会话生效
  1. 项目根写 `MEWCODE.md`：「回答末尾加一行 —— MewCode」，并含一行 `@docs/rules.md`（内容「变量名一律用 snake_case」）和一行 `@Override`。
  2. 启动 MewCode → 无指令告警；问「本项目有哪些规范」→ 回答提到 snake_case 且末尾有签名。
  3. 说「以后回复都尽量控制在三句话以内，记住」→ 本轮结束后片刻出现「已更新记忆：…」提示，期间输入框可用；`~/.mewcode/memory/` 下出现带 frontmatter 的笔记，`MEMORY.md` 有对应行。
  4. 本会话内修改 `MEWCODE.md` 删掉签名要求并再提问 → 回答仍带签名（快照不变）。
  5. `/exit` 后重启，直接问一个开放问题 → 回答遵守「三句话以内」、不再带签名。
- [ ] 场景 2：中断后恢复
  1. 新会话中让 MewCode 读一个文件并总结，再说「记住数字 42」。
  2. 检查 `.mewcode/sessions/` 下的 JSONL：行数与对话一致，含工具调用与结果。
  3. 直接关掉 tmux 窗格（模拟崩溃），重新启动；输入 `/resume` → 列表中出现该会话，标题是第一句话，消息数正确。
  4. Esc 取消 → 对话不变；再次 `/resume` 选中 → 聊天区出现分隔线、历史用户消息与助手回复（无工具结果原文）和「已恢复会话」提示。
  5. 问「刚才让你记住的数字是多少」→ 回答 42；会话文件行数继续增长（续写原文件）。
- [ ] 场景 3：异常会话恢复
  1. 复制一份会话文件，手工把中间某行改成乱码、删掉最后一行的后半截，并把末尾改成一条带工具调用但无结果的助手消息；把所有 ts 改到 2 天前。
  2. `/resume` 选中它 → 提示中含跳过行数、「末尾未完成的工具调用已截断」、「距上次对话已过去 2 天」。
  3. 继续提问 → 模型正常回复，无协议错误。
- [ ] 场景 4：过期清理
  1. 在 sessions 下放两份会话文件，mtime 分别设为 31 天前与 29 天前。
  2. 启动 MewCode → 31 天前的被删除，29 天前的保留并出现在 `/resume` 列表中。
- [ ] 场景 5：边界操作
  1. 在一个从未用过的目录启动 → `/resume` 提示「暂无历史会话」。
  2. 在该目录发一个耗时请求，运行中输入 `/resume` 回车 → 提示「暂无历史会话」，本轮继续跑完。
  3. 在已有历史会话的项目里发一个耗时请求（如「逐个读取 src 下所有文件并总结」），运行中输入「你好」回车 → 出现「仅支持 /resume」提示，输入框里仍是「你好」，本轮继续。
  4. 清空输入框，输入 `/resume` 回车 → 出现「本轮已中断」，随后弹出会话列表；选中一个会话 → 恢复成功；本轮之后没有出现「已更新记忆」提示。
  5. 一轮刚结束（记忆更新进行中）立即 `/exit` → 进程立即退出，`~/.mewcode/memory/` 下无半截文件或 `.tmp` 残留。
- [ ] 场景 6：两个实例并发
  1. 同一项目开两个 tmux 窗格，各启动一个 MewCode（A、B），各发一条消息。
  2. B 输入 `/resume` → 列表中 A 的会话标注「使用中」；选中它 → 提示「正在被另一个 MewCode 使用」，B 的对话不变。
  3. A 与 B 几乎同时各说一句「记住：我喜欢用 tab 缩进」/「记住：本项目用 bun test」→ 两边都出现「已更新记忆」或其中一边静默；之后 `~/.mewcode/memory/` 与 `.mewcode/memory/` 下无 `.tmp`，各自 `MEMORY.md` 的行与笔记文件一一对应；`.mewcode/locks/memory.lock` 不存在。
  4. 在 A 的窗格直接 kill 进程（模拟崩溃），`.mewcode/locks/sessions/` 下 A 的锁文件仍在；B 再次 `/resume` → A 的会话不再标注「使用中」，选中后正常恢复。
  5. 退出 B → B 的会话锁文件被删除。
