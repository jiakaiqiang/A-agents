typescript/src · agent loop

MewCode 调用链：从一句输入到工具执行

用户在输入框回车后，消息进入 ConversationManager，由 runLoop 驱动「调模型 → 执行工具 → 结果回灌」的 ReAct 循环，直到模型不再请求工具。全链路只靠 AgentEvent 事件流把进度送回 Ink 界面。

逐段对照源码

每一段在哪个文件

启动装配main.tsx
  • loadConfig 读 provider；createDefaultRegistry 注册 Read / Write / Edit / Bash / Glob / Grep 和 toolSearch。
  • McpManager.connectAll 阻塞连接 MCP，把远端工具注册进同一个 registry，失败按 Server 降级。
会话准备tui/app.tsx
  • 选定 provider 后构建系统提示词（稳定段 + 环境段），createClient 按 protocol 动态加载 Anthropic 或 OpenAI 适配器，同时创建 Compactor。
提交输入tui/app.tsx
  • handleSubmit 先拦斜杠命令（/plan /do /compact 等，不发请求），普通文本写入历史后建 AbortController，调 runAgentLoop。
  • runAgentLoop 组装 LoopOptions：client、conversation、registry、权限 Gate、compactor、signal、本轮 reminders。
主循环agent/loop.ts
  • 每次迭代：maintain 兜底压缩 → 生成工具定义和懒加载目录 → collectStream。
  • toolUses 为空即自然完成；否则先写助手消息，再执行工具、回灌结果，进入下一次迭代。
  • 停止条件：25 轮上限、连续 3 轮全是未知工具、用户 Esc、请求异常。非自然停止时补一条收尾助手消息。
模型请求llm/anthropic.ts
  • buildAnthropicMessages 把内部 Message 映射成协议格式：assistant 带 thinking / text / tool_use 块，toolResults 变成 tool_result 块。
  • 流式解析：input_json_delta 按 block index 累积参数，content_block_stop 时统一 JSON.parse，失败记 parseError。
收集响应agent/collect.ts
  • 一次消费流同时做两件事：yield 文本增量给界面，return 完整的 text、thinkingBlocks、toolUses、usage 给循环。Esc 中断转成 aborted: true。
批次调度agent/batch.ts
  • planBatches 保序扫描，相邻只读调用并成并发批，有副作用的单独串行；runBatches 按原始顺序回写结果。
单次执行tools/execute.ts
  • runTool 依次做：查找（懒池补载）→ Schema 校验 → decide → execute → 截断与脱敏。
权限判定permission/decide.ts
  • 黑名单与沙箱只会拒绝；规则层可放行或拒绝；档位兜底表决定 allow 或 ask；ask 时通过 Promise 挂起等 ConfirmBox，选「本会话 / 永久」会写入规则。
回到界面tui/app.tsx
  • for await 消费 AgentEvent：text 进流式区，tool_start / tool_end 原地画工具行，usage 刷新状态栏，done 定稿并显示完成标记。
设计要点

串起这条链的几个约定

事件流是唯一出口

runLoop、collectStream、runBatches 都是 async generator，只 yield AgentEvent，不 import 任何界面模块，循环可以脱离 Ink 单测。

tool_use 与 tool_result 严格配对

参数解析失败、未知工具、权限拒绝、中断都会生成一条错误结果，结果数组与调用数组长度始终相等。

补充指令不进历史

计划模式指令和懒加载目录每次请求临时挂到末条 user 消息，切模式不污染历史，也不破坏系统提示词的缓存前缀。

权限在执行之前

decide 拿的是 Schema 归一化后的参数，拒绝时工具不会产生任何副作用；Esc 时挂起的确认会按拒绝兑付，循环能正常收尾。
