# Agent Loop Spec

## 背景

第二章已经建好工具层（六个核心工具、注册中心、参数校验、路径边界、脱敏、资源上限），
以及一个受限的单轮闭环：每轮最多两次模型请求、最多执行一个工具，第二次请求不携带
工具定义。模型即便还想继续也只能停下，用户必须为每一步手动追问，一个多步任务被切成
很多轮对话。

本章把这个受限闭环替换为自主循环：模型可以在一轮内连续思考、调用工具、读取结果、
根据结果调整下一步，直到它自己认为任务完成。同时把编排层与界面彻底解耦，为后续章节
（权限确认、上下文压缩）留出接入位置。

## 目标

- 用 ReAct 模式的迭代循环替换固定两段式：一轮内可发起多次模型请求，每次工具结果
  回写后继续迭代，直到模型不再请求工具。
- 提供完备且可区分的停止条件，迭代上限作为兜底安全网，任何情况下循环都必须终止。
- 编排层通过异步事件流向外输出过程，不持有任何界面对象、也不接收界面传入的函数；
  界面只消费事件流。
- 流式收集器双路工作：文本增量实时推给事件流，同时攒出完整响应供循环判断下一步。
- 同次响应包含多个工具调用时按安全性分批：可并发的工具并发执行，有副作用的工具串行
  执行，且不改变模型给出的调用顺序。
- 提供两段式 Plan Mode：`/plan` 只向模型暴露读类工具，让它先产出计划；`/do` 切回
  全部工具去执行。
- 循环产生的会话历史在任何停止路径下都保持合法：工具调用与工具结果严格配对，下一轮
  请求可正常发出。

## 功能需求

### 一、循环编排

- F1: ReAct 迭代循环
  每次用户提交后进入一个迭代循环。单次迭代的步骤固定为：(a) 向模型发起一次携带当前
  可用工具定义的请求；(b) 流式收集该次响应的文本、思考内容与工具调用；(c) 若响应
  包含工具调用，则把助手响应与工具执行结果写入会话历史，迭代计数加一，进入下一次
  迭代；(d) 若响应不含任何工具调用，则该响应的文本即为本轮最终答复，循环结束。
  一轮内的模型请求次数不设固定值，由模型行为与停止条件共同决定。系统提示词不再声明
  「每轮最多执行一个工具」，改为说明可以在一轮内多次调用工具、根据结果继续，直到
  任务完成。

- F2: 迭代计数与上限
  每轮维护本轮已发起的模型请求次数。系统有一个集中配置的迭代上限，作为兜底安全网。
  达到上限时不再发起新的模型请求，循环以「达到迭代上限」原因结束。上限的默认值需在
  实现层单点声明，可调整而不需修改循环逻辑。

- F3: 历史配对不变式
  每次迭代若产生工具调用，则该次迭代必须向历史写入一条包含全部工具调用的助手消息，
  紧随其后写入一条包含全部对应结果的消息，二者按调用标识严格一一配对。未被执行的
  调用（参数解析失败、未知工具、批次被中断）同样必须有一条结果，不得静默丢弃。

- F4: 停止时的历史收尾
  循环因非自然原因停止（迭代上限、用户取消、连续未知工具、流错误）时，若此刻历史
  末尾是工具结果消息而没有对应的助手答复，需补写一条说明本轮为何结束的助手消息，
  保证历史形态在三种协议下均合法、下一轮请求不因缺少助手回应而失败。

### 二、停止条件

- F5: 自然完成
  模型响应不含任何工具调用时循环结束，该响应文本为本轮最终答复，不再发起额外请求。

- F6: 达到迭代上限
  已发起的模型请求次数达到配置上限时循环结束，向用户给出明确提示，说明本轮因达到
  上限而中止以及已执行的迭代数。

- F7: 用户取消
  用户可在任意阶段（模型流进行中、工具批次执行中、两次迭代之间）取消本轮。取消后
  正在进行的模型流与子进程尽力终止，不再发起新的模型请求，已完成的调用与结果保持
  配对写入历史，会话保持可用。

- F8: 连续未知工具调用
  某次迭代的全部工具调用都指向注册中心中不存在的工具时，记为一次「无效迭代」。连续
  无效迭代达到配置阈值时循环结束，避免模型在不存在的工具上反复空转。任一次迭代中只要
  有一个已登记工具被执行，连续计数即归零。

- F9: 流错误
  模型请求或流式解析过程抛出非取消类错误时循环立即结束，错误信息向用户可见，已完成的
  工具调用与结果保持配对，会话保持可用，用户可继续输入下一条消息。

- F10: 停止原因可观测
  循环结束时返回可区分的停止原因，覆盖上述五种情况。停止原因同时通过事件流对外发出，
  界面据此呈现不同措辞。

### 三、异步事件流

- F11: 事件流驱动
  编排层对外只提供一个异步事件序列：调用方逐个取事件并自行决定如何呈现。编排层不引用
  任何界面模块，也不接收界面传入的回调函数。

- F12: 事件类型集合
  事件流至少覆盖六类：(a) 文本增量，模型正文的流式片段；(b) 思考增量，扩展思考的
  流式片段；(c) 工具调用开始，含调用标识、工具名与可安全展示的参数摘要；(d) 工具
  结果，含调用标识、成功与否、一行结果摘要；(e) Token 用量，本轮累计的输入、输出与
  缓存 token；(f) 进度，含当前迭代序号、当前阶段（模型请求中 / 工具执行中）与本轮
  已执行工具数。此外需有一类提示事件用于承载停止原因与非致命告知（如已跳过的调用）。

- F13: 事件顺序保证
  事件的到达顺序与实际发生顺序一致：同一迭代内，进度事件先于该迭代的文本与工具事件；
  同一工具的「调用开始」必先于其「结果」；本轮结束事件在所有其他事件之后。

- F14: 界面零耦合
  界面对循环内部的迭代次数、批次划分、协议差异无感知，仅依据事件类型渲染。新增一类
  事件时，未处理该类型的界面不应崩溃或错乱。

### 四、流式收集器

- F15: 双路收集
  单次模型请求的流式响应由一个收集器统一消费，同时做两件事：把文本与思考增量即时转成
  事件推给调用方；把完整内容累积成一个结构化的响应对象。二者基于同一次流消费，不重复
  请求、不重复计费。

- F16: 完整响应内容
  收集器产出的响应对象至少包含：完整正文文本、思考块列表、工具调用列表（含调用标识、
  工具名、已解析参数，以及参数解析失败时的失败原因）、模型给出的停止原因、本次请求
  的 Token 用量、本次流是否被取消。循环仅依据该对象判断下一步，不再回看原始事件。

- F17: 参数解析失败不执行
  分片到达的参数 JSON 拼接后无法解析时，对应调用不得执行，直接生成参数错误的结构化
  结果并参与配对回写。

### 五、工具批次调度

- F18: 工具安全性声明
  每个工具在自身定义中声明是否可与其他工具并发执行。只读类操作（读文件、找文件、
  搜内容）声明为可并发；产生副作用的操作（写文件、改文件、执行命令）声明为不可并发。
  调度器只读取该声明，不内置工具名清单。

- F19: 保序分段分批
  同次响应含多个工具调用时，按模型给出的原始顺序扫描，把相邻的同类调用切成连续批次：
  相邻的可并发调用归入同一并发批；每个不可并发调用单独成一个串行批。批次之间严格
  按顺序依次执行，不重排、不合并跨越串行批的并发调用。

- F20: 并发批执行
  同一并发批内的调用同时发起，全部完成后按调用在响应中的原始顺序回写结果。批内某个
  调用失败不影响同批其他调用，也不终止批次与循环。

- F21: 串行批执行
  串行批只含一个调用，等其完全结束后才进入下一批。前一批的副作用对后一批可见。

- F22: 批次中断
  用户在批次执行中取消时，已完成的调用保留其真实结果，尚未开始的调用生成「已取消」
  的结构化结果，全部调用仍与助手消息中的调用一一配对写入历史。

### 六、Plan Mode

- F23: 会话模式状态
  会话维护一个当前模式，取值为「计划模式」或「执行模式」，默认执行模式。模式在同一
  会话内持续有效，直到用户显式切换；切换不清空对话历史。

- F24: 切入计划模式
  用户输入 `/plan` 后进入计划模式。该模式下向模型暴露的工具仅限只读类工具，写文件、
  改文件、执行命令不出现在工具定义中。循环机制本身不变：模型仍可多次迭代读取信息，
  最终产出计划文本。该命令本身不作为用户消息发给模型，也不写入会话历史。

- F25: 切回执行模式
  用户输入 `/do` 后回到执行模式，恢复全部工具。两个命令都是纯模式开关：只切换模式并
  给出确认提示，不代替用户向模型发起请求；模式生效于用户的下一条消息。该命令同样
  不作为用户消息发给模型，也不写入会话历史。

- F26: 模式进入模型视野
  当前模式与该模式下的行为约束需进入模型可见的提示内容：计划模式下明确说明只能读取
  信息、应当产出计划而不是直接改动；执行模式下不施加该约束。模式切换后的下一次请求
  即生效。

- F27: 模式在界面可见
  当前模式在界面上持续可见，用户不需要回翻历史就能知道自己处于哪个模式。

### 七、终端呈现

- F28: 迭代过程可见
  一轮内多次迭代的文本与工具行按发生顺序累积呈现，不互相覆盖。上一次迭代的正文在
  下一次迭代开始时保留在历史区，不被新的流式文本冲掉。

- F29: 进度可见
  循环运行期间界面显示当前迭代序号与所处阶段，用户能判断系统是在等模型还是在跑工具。

- F30: 停止原因呈现
  五种停止原因在界面上以可区分的措辞呈现；自然完成不额外提示，其余四种给出明确说明。

- F31: 累计用量
  用量显示覆盖本轮全部模型请求的累计输入、输出与缓存 token，而非最后一次请求的数值。

## 非功能需求

- N1: 上限集中配置
  迭代上限、连续无效迭代阈值与并发批的最大并发度在实现层集中单点声明，与既有工具资源
  上限放在一处，调整时不触碰循环逻辑。

- N2: 循环必然终止
  不存在任何输入或模型行为能让循环无限运行。迭代上限对全部路径生效，包括模型持续请求
  工具、持续请求未知工具、工具持续失败等情况。

- N3: 中断响应性
  取消信号在模型流与工具执行两处都能及时生效，长时间命令执行期间界面保持响应与可中断。
  取消后不残留正在运行的子进程。

- N4: 向后兼容
  模型不请求工具时，交互与呈现与前两章的纯文本对话完全一致：一次请求、流式正文、
  markdown 呈现。配置文件格式保持兼容，不新增必填字段。

- N5: 错误隔离
  单个工具失败、单次迭代异常、参数解析失败都不得冒泡到界面渲染或事件循环。任何失败后
  会话必须仍可继续输入下一条消息。

- N6: 并发安全
  同一并发批内的工具执行不共享可变状态；结果顺序由调用在响应中的原始位置决定，与实际
  完成先后无关，同一输入下的结果顺序可复现。

- N7: 可扩展性
  新增工具只需在自身定义中声明并发安全性并在注册中心登记，不需修改循环、调度器、事件
  流或界面代码。计划模式的可用工具集由工具自身声明派生，不存在需要同步维护的第二份
  工具名单。

- N8: 可测试性
  循环、调度器与收集器均不依赖界面与真实网络：用可编程的假模型客户端驱动，把事件流
  收成序列后即可断言迭代次数、事件顺序、停止原因与历史配对。测试通过既有测试命令运行，
  类型检查无错误。

- N9: 可观测性
  循环结束时可取到：模型请求次数、工具执行次数、停止原因、是否被取消。每个失败结果
  仍可定位到具体原因类别。事件流本身足以复现一轮的完整过程。

- N10: 上下文效率
  本章不引入历史压缩，但循环产生的历史必须避免可避免的膨胀：单条工具结果沿用既有截断
  约束；不重复写入同一次响应；不因迭代而重复注入系统提示内容。既有的提示词缓存标记
  策略保持不变。

- N11: 密钥不回显
  沿用既有约束：事件流中的参数摘要、结果摘要、错误信息与停止提示均不得出现密钥值；
  脱敏仍在工具执行出口统一处理，循环层不新增第二套脱敏逻辑。

- N12: 代码风格一致性
  新增代码遵循现有约定：严格类型检查、模块按领域分层、中文行内注释、错误类集中定义。
  不引入与现有依赖重复的第三方库。

## 不做的事

- 权限确认系统：工具在工作目录内直接执行，不做逐次授权或危险操作拦截。
- 上下文压缩与历史摘要：只沿用单条工具结果截断，不做超长历史的压缩或裁剪。
- 用户交互式确认：循环运行期间不向用户提问、不等待用户输入后再继续。
- 计划的结构化产物：Plan Mode 只产出计划文本，不落盘、不解析成任务列表、不做计划与
  执行的自动对照。
- 待办清单类工具与状态类工具。
- 子 Agent / 任务分发类工具：不做工具内再起循环。
- MCP 工具接入、网络类工具。
- 会话持久化：循环历史不落盘，重启后从空白开始。
- 扩展思考内容的渲染：思考增量进入事件流但界面不展示。
- 工具结果的折叠展开、翻页等交互；工具行仍只显示摘要。
- 迭代过程的重放与回滚：不支持撤销某次迭代的副作用。

## 验收标准

### 循环编排

- AC1: (F1) 模型第一次响应即不含工具调用时，本轮只发起一次请求，该响应文本为最终
  答复；系统提示词不再包含「每轮最多执行一个工具」的约束。
- AC2: (F1) 模型连续三次请求工具、第四次不请求时，本轮共发起四次模型请求，执行三批
  工具，最终答复为第四次响应的文本。
- AC3: (F1/F3) 每次含工具调用的迭代都在历史中留下一条助手工具调用消息与紧随其后的
  一条结果消息，调用标识一一配对，无孤立调用、无孤立结果。
- AC4: (F2) 迭代上限设为 N 时，模型持续请求工具的场景下模型请求次数恰为 N，之后不再
  发起请求。
- AC5: (F4) 因迭代上限、取消、连续未知工具、流错误停止且历史末尾为工具结果时，历史
  被补上一条说明性助手消息；随后再发起一轮请求能正常构造消息、不报缺少配对。

### 停止条件

- AC6: (F5/F10) 自然完成时停止原因为「完成」，界面不额外提示。
- AC7: (F6/F10) 达到迭代上限时停止原因可区分，界面提示包含已执行迭代数。
- AC8: (F7) 在模型流进行中取消：流终止，不再发起新请求，历史配对完整，可继续输入
  下一条消息。
- AC9: (F7/F22) 在工具批次执行中取消：已完成调用保留真实结果，未开始调用得到「已
  取消」结果，全部调用与助手消息配对。
- AC10: (F8) 模型连续请求不存在的工具达到阈值时循环结束、停止原因可区分；其间任一次
  迭代成功执行了已登记工具时连续计数归零、循环继续。
- AC11: (F9) 模型请求抛出非取消错误时循环立即结束，错误对用户可见，会话仍可继续输入。
- AC12: (N2) 构造一个永远请求工具的假模型客户端，循环在迭代上限处终止，不无限运行。

### 事件流

- AC13: (F11/F14) 编排层代码不引用任何界面模块，也不存在界面传入的回调参数；替换
  界面实现无需改动编排层。
- AC14: (F12) 一轮含工具调用的运行中，事件序列同时出现文本增量、工具调用开始、工具
  结果、Token 用量、进度与停止提示六类事件。
- AC15: (F13) 收集事件序列后断言：进度事件先于同迭代的文本与工具事件；同一调用标识的
  「开始」早于其「结果」；结束事件位于序列末尾。

### 流式收集器

- AC16: (F15) 单次请求只消费一次流：文本增量事件的拼接结果与完整响应对象的正文文本
  完全一致。
- AC17: (F16) 完整响应对象可分别取到正文、思考块、工具调用列表、停止原因与用量；
  含参数解析失败的调用时该调用带有失败原因。
