# Skill 系统（一期）Spec

## 背景
MewCode 现在有斜杠命令（其中 `/review` 是提示词类命令）、延迟工具目录配合 `toolSearch` 按需加载、每轮注入的 system-reminder，系统提示词里也预留了 Skills 段位。但这些能力是零散的：
- 想复用一段 SOP，要么每次手敲，要么写死成内置命令。
- 没办法按任务收窄可用的工具。
- 没办法把子任务放进独立的上下文里跑，避免污染主对话。

本期为 Skill 系统一期：核心能力 + 独立执行模式。目录型 Skill 的专属工具与热更新属于二期。

## 目标
- 把可复用的 AI 操作写成 Markdown 文件，分两类：
  - 内部 Skill：随程序发布，本期内置 commit、review、test 三个样板。
  - 外部 Skill：分项目级（`.mewcode/skills/`）和用户级（`~/.mewcode/skills/`），两级都支持单文件（`<名字>.md`）和目录型（`<名字>/SKILL.md`）两种写法。
  - 同名时按「项目级 > 用户级 > 内部」覆盖。
- 两阶段加载：启动时模型只看到名字和一句说明，用到时再加载完整指令。
- 已激活 Skill 的指令每轮都在，可以同时激活多个；用工具白名单收窄可用工具，提高模型选对工具的准确率。
- 支持共享和独立两种执行模式，独立模式跑完后把结果摘要回流到主对话。
- 内部和外部 Skill 启动时自动加载并注册成斜杠命令，出现在 `/help` 和补全列表里；`/skills` 用来查看和停用。

## 功能需求

- F1: Skill 定义格式
  一个 Skill 由 YAML frontmatter（元信息）和 Markdown 正文（发给模型的 SOP）组成。frontmatter 字段：
  `name`（必填，小写字母、数字、连字符，必须与文件名或目录名一致）、`description`（必填，非空单行）、
  `tools`（可选，工具名列表，不写表示不收窄）、`mode`（`shared` 或 `isolated`，默认 `shared`）、
  `history`（仅 `isolated` 有效，非负整数，默认 0）、`model`（可选，仅 `isolated` 有效）。正文不能为空。
  缺必填字段、字段类型不对、`mode` 非法、名字不合法、正文为空、frontmatter 解析失败时，跳过该 Skill 并告警；
  出现未知字段，或共享模式下写了 `history`/`model`（被忽略）时，只告警不跳过。

- F2: 参数占位符
  正文中每一处 `$ARGUMENTS` 替换为调用参数（去首尾空白），没传参数替换为空串；正文没有 `$ARGUMENTS` 但传了参数时，参数追加到正文末尾，中间空一行。

- F3: 发现与覆盖
  启动时一次性加载内部 Skill、用户级 `~/.mewcode/skills/`、项目级 `<工作目录>/.mewcode/skills/`。
  外部目录只扫描第一层：`<名字>.md` 为单文件 Skill，`<名字>/SKILL.md` 为目录型 Skill（一期只读 SKILL.md）。
  同层同名的单文件与目录型并存时用目录型并告警；不同层同名时按「项目级 > 用户级 > 内部」覆盖。
  目录不存在视为空；单个 Skill 失败只跳过它自己，不影响其他 Skill，也不影响启动。

- F4: 白名单校验
  启动时检查每个 Skill 的 `tools`：每个名字都必须是本次启动实际可用的工具（内置工具、已连上的 MCP 工具、延迟登记的 MCP 工具）。
  有不存在的工具时跳过该 Skill，告警写明文件路径和工具名。加载工具是系统级的，写不写进白名单都不算错。

- F5: 注册为斜杠命令
  每个加载成功的 Skill 注册为同名斜杠命令（带描述、用法 `/<名字> [参数]`、接受参数），出现在 `/help` 与补全中并标明是 Skill。
  review Skill 取代原 `/review` 提示词命令，原定义删除。Skill 名与其他内置命令的名称或别名冲突时，跳过该 Skill 并告警，内置命令不变。
  Skill 命令在 Agent 运行中不可用，被拒提示与其他不可运行中的命令一致。

- F6: 第一阶段：目录注入
  启动后模型能看到全部可用 Skill 的名字、一句说明，以及「需要时调用加载工具」的用法提示；没有任何 Skill 时不注入。本期不做热更新，目录在会话内不变。

- F7: 第二阶段：加载工具
  提供一个系统级内置工具，模型传入 Skill 名字与可选参数：共享模式下激活该 Skill（同 F8），返回「已激活」及其可用工具；
  独立模式下运行子对话（同 F11），把结果摘要作为工具结果返回；名字不存在时返回可用 Skill 列表，不报异常。该工具始终对模型可见，不受白名单约束。

- F8: 共享模式激活与钉住
  激活时先按 F2 替换参数，再把替换后的全文钉进环境上下文：位于系统提示词之后、对话历史之前，每次模型请求都重新带上。
  钉住内容不写入对话历史，压缩上下文不会丢失它。可同时激活多个，按激活顺序排列；同一 Skill 再次激活时原位替换，不叠加。

- F9: 共享模式斜杠调用
  输入 `/<名字> <参数>` 等于先激活（同 F8）再发起一轮对话：对话区显示用户输入的原命令，模型收到一条简短触发语（如「执行 Skill commit，参数：修复登录超时」）。
  会话存档保留原命令，`/resume` 恢复后仍显示原命令。

- F10: 工具白名单
  下发给模型的工具 = 所有已激活 Skill 白名单的并集 + 加载工具；没有激活任何 Skill，或任一已激活 Skill 没写白名单时不收窄。
  只有可用集合包含 `toolSearch` 时才注入延迟工具目录。模型调用不在可用集合里的工具时不执行，回灌「该工具不在当前可用工具中」。
  白名单不改变权限判定：可用集合内的工具照旧走档位、规则与确认。

- F11: 独立模式执行
  子对话初始内容为主历史最近 `history` 条消息加替换参数后的 SOP（作为一条用户消息）；截取时不拆开工具调用与其结果，必要时少取。
  子对话可用工具为该 Skill 的白名单（不写即全部），不含加载工具（不可嵌套）；跑完整的 Agent 循环，权限判定与确认交互与主对话相同；写了 `model` 时用当前 provider + 指定模型名。
  运行期间对话区照常显示工具行并带 Skill 名前缀，Esc 可中断。结束后主历史只追加两条：用户原命令，以及「【Skill <名字> 结果】+ 子对话最后一条回复」；中断或失败时追加失败说明。
  子对话本身不进主历史、不进会话存档；独立 Skill 不进入已激活集合，不钉住，不收窄主对话工具。

- F12: 查看与停用
  `/skills` 列出全部可用 Skill（名字、说明、模式、来源层级），标出已激活的；`/skills off <名字>` 停用一个，`/skills off` 停用全部；名字不存在或未激活时给出提示。
  停用后钉住内容消失、白名单重新计算。`/clear` 时一并停用全部 Skill；`/resume` 恢复后已激活集合为空（激活状态不存档）。

- F13: 内部样板
  `commit`（共享）：查看状态与 diff，按约定格式生成提交说明并提交，参数为提交说明关注点。
  `review`（共享）：用 git diff 审查未提交改动，参数为审查范围，行为与原 `/review` 一致。
  `test`（独立）：识别项目测试命令并运行，汇总失败原因，参数为测试范围。三个样板都写了白名单。

- F14: 启动报告
  所有 Skill 告警与已有启动告警一并显示，每条写明来源路径与原因；另显示一条加载摘要，如「已加载 Skill 5 个（内部 3、用户 1、项目 1）」。

## 非功能需求
- N1: 第一阶段每个 Skill 只占目录一行（名字 + 一句说明，说明超 80 字符截断）；完整指令只在激活后进入上下文。
- N2: Skill 目录会话内不变，放在稳定段；钉住指令单独成段放在稳定段之后。激活或停用 Skill 不改变稳定段字节，已建立的缓存前缀继续命中。
- N3: 加载 Skill 只读本地文件、不发网络请求；几十个 Skill 时启动无明显变慢。
- N4: 单个文件出问题（不可读、frontmatter 损坏、编码错误、字段非法）只跳过该 Skill 并告警，不导致启动失败、不影响其他 Skill；加载工具或子对话执行抛出的异常转为错误结果或提示，主会话继续可用。
- N5: 只读取 skills 目录第一层与 `<名字>/SKILL.md`，解析后路径必须仍在对应 skills 目录内，指向目录外的符号链接跳过；单个 Skill 文件超过 64KB 跳过并告警；frontmatter 用安全模式解析，不执行任何代码。
- N6: 白名单只减少模型可见的工具，不让工具绕过黑名单、路径沙箱、档位与确认；独立模式子对话同样走这套权限判定。
- N7: 没有激活任何 Skill 时，下发的工具列表只比现在多一个加载工具，系统提示词稳定段只多一段 Skill 目录，每轮补充指令与现在一致；现有斜杠命令只有 `/review` 被 review Skill 取代，其余行为不变；现有测试全部继续通过。
- N8: 解析、发现、白名单计算、钉住文本生成、参数替换不依赖终端渲染框架，可单独单元测试；独立模式执行器可注入假的模型客户端测试。
- N9: 独立模式子对话运行期间界面照常显示进度与工具行，中断响应速度与主对话一致。

## 不做的事
- Skill 市场分发、版本管理、远程安装与更新。
- 目录型 Skill 的专属工具（tools/ 下的 schema 与实现脚本）；一期目录型 Skill 只读取 SKILL.md。
- 热更新：运行中新增、修改、删除 Skill 文件不生效，需重启。
- Skill 嵌套：子对话里不能再加载 Skill；SOP 里引用其他 Skill 不会自动展开。
- 位置参数（`$1`、`$2`）、具名参数、模板变量与条件逻辑；只支持整串 `$ARGUMENTS`。
- 激活状态持久化：激活集合不写入会话存档，也不跨进程保留。
- 独立模式切换 provider（只能换模型名）；独立模式的额外摘要请求（最后一条回复即摘要）。
- 子对话历史的存档与回放。
- 白名单之外的工具级参数限制（如只允许 `Bash(git *)`）——仍由权限规则负责。

## 验收标准
- AC1 (F1): 分别缺 name、缺 description、mode 为非法值、name 含大写、正文为空、frontmatter 不是合法 YAML → 该 Skill 未加载，启动告警含文件路径与原因；含未知字段或共享模式写了 model → 加载成功并有告警。
- AC2 (F2): `$ARGUMENTS` 出现两次时都被替换；无参时替换为空；正文无占位符而传了参数时，参数出现在正文末尾。
- AC3 (F3): 内部、用户、项目三层各放一个同名 Skill → 生效的是项目级；删掉项目级后生效用户级；同层 `x.md` 与 `x/SKILL.md` 并存 → 用目录型并告警；`x/` 下的其他文件不被当作 Skill。
- AC4 (F3, N4): 一个 Skill 文件损坏、另一个正常 → 启动成功，正常的可用，损坏的有告警；skills 目录不存在时启动无告警。
- AC5 (F4): 白名单含不存在的工具 → 该 Skill 未加载，告警写明路径与工具名；白名单含已连上的 MCP 工具名 → 正常加载。
- AC6 (F5): `/help` 与补全中出现全部 Skill 并标明是 Skill；`/review` 执行的是 review Skill；名为 `clear` 或 `h` 的外部 Skill 被跳过并告警，`/clear`、`/help` 行为不变；Agent 运行中输入 Skill 命令被拒。
- AC7 (F6, N1): 第一次模型请求中可见全部 Skill 的名字与说明，看不到任何 SOP 正文；超长说明被截断；无 Skill 时请求中不含目录。
- AC8 (F7): 模型调用加载工具加载共享 Skill → 工具结果含「已激活」，下一次请求中出现该 SOP；加载独立 Skill → 工具结果为子对话摘要；传不存在的名字 → 结果列出可用 Skill；激活了带白名单的 Skill 后加载工具仍在工具列表里。
- AC9 (F8, N2): 激活 A、B 后每次请求都带两段 SOP 且顺序为 A、B；再次激活 A 后仍只有一段 A 且内容为新参数；压缩上下文后 SOP 仍在；激活前后系统提示词稳定段字节相同。
- AC10 (F9): `/commit 修复登录超时` → 对话区显示原命令，模型收到触发语，下一次请求含替换后的 SOP；`/resume` 恢复该会话后显示原命令。
- AC11 (F10, N6): 激活 [Bash, Read] 与 [Read, Grep] 两个 Skill → 下发工具恰为 Bash、Read、Grep 加载工具；再激活一个无白名单的 Skill → 恢复全部工具；模型调用列表外工具 → 未执行并回灌提示；白名单内的 Bash 在默认档仍弹确认。
- AC12 (F10): 白名单不含 toolSearch 时请求中不出现延迟工具目录；含 toolSearch 时出现。
- AC13 (F11): `/test src/auth`（独立，history: 2）→ 子对话请求含主历史最近 2 条（不拆工具配对）与 SOP；子对话工具列表不含加载工具；结束后主历史只多两条且第二条以「【Skill test 结果】」开头；写了 model 的独立 Skill 子对话请求使用该模型名。
- AC14 (F11, N9): 独立 Skill 运行中对话区出现带前缀的工具行；按 Esc 中断 → 主历史追加失败说明，会话继续可用；会话存档中不含子对话消息。
- AC15 (F12): `/skills` 列出名字、说明、模式、来源并标出已激活；`/skills off commit` 后下一次请求不含 commit SOP、白名单重算；`/skills off` 清空全部；`/clear` 与 `/resume` 后已激活集合为空。
- AC16 (F13): 三个内部样板全部加载成功，模式与白名单符合定义；`/review src/tui` 的模型请求含 git diff 指令与审查范围。
- AC17 (F14): 启动告警逐条列出每个被跳过的 Skill 与原因；显示加载摘要且计数与实际一致。
- AC18 (N5): 指向 skills 目录外的符号链接未被加载；超过 64KB 的 Skill 文件被跳过并告警。
- AC19 (N7): 不放任何外部 Skill、不激活 Skill 时，现有全量测试与类型检查通过；请求中的工具列表等于现有工具加一个加载工具，补充指令与现在一致。
