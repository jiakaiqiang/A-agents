# Skill 系统（一期）Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。
> 验证命令在 typescript/ 下执行。「单测」指 `bun test tests/skills/`，「集成测试」指用脚本化假模型驱动 Agent 循环的测试，「Ink 测试」指以子进程驱动真实 Ink 界面的 Skill 系统测试，「手工」指在真实终端 `bun run start` 用真实 provider 操作。
> 验收记录：`bun run typecheck` 零错误；`bun test` 546 pass / 1 skip / 0 fail；Skill Ink fixture 与斜杠命令 Ink fixture 均通过；三次变异检验（去掉白名单拦截、去掉钉住传参、子对话内容泄进主历史）均在对应步骤失败，还原后通过；skills 目录无 ink/react/tui/commands 导入，agent 目录无 skills 导入。未勾选项需在真实终端手工验收（本机无 tmux）。

## 定义与解析

- [x] 缺 name、缺 description、mode 非法、name 含大写、正文为空、frontmatter 不是合法 YAML 时，该 Skill 未加载，告警含文件路径与原因（验证：单测 + Ink 测试；AC1）
- [x] 含未知字段、共享模式写了 model 或 history 时，Skill 照常加载并给出告警，被忽略的字段不生效（验证：单测；AC1）
- [x] name 与文件名或目录名不一致时，该 Skill 未加载并告警（验证：单测；F1）
- [x] 带 BOM、CRLF 换行的 Skill 文件可正常解析（验证：单测；N4）
- [x] `$ARGUMENTS` 出现两次时都被替换；无参时替换为空；正文无占位符而传了参数时，参数出现在正文末尾且中间空一行；参数里的 `$&` 原样保留（验证：单测；AC2）

## 发现、覆盖与安全读取

- [x] 内部、用户、项目三层各放一个同名 Skill → 生效项目级；去掉项目级后生效用户级（验证：单测 + Ink 测试；AC3）
- [x] 同层 `x.md` 与 `x/SKILL.md` 并存 → 用目录型并告警；`x/` 下的其他文件不被当作 Skill（验证：单测；AC3）
- [x] 一个 Skill 文件损坏、另一个正常 → 启动成功，正常的可用，损坏的有告警；skills 目录不存在时启动无告警（验证：单测；AC4）
- [x] 白名单含不存在的工具 → 该 Skill 未加载，告警写明路径与工具名；白名单含本次已连上的 MCP 工具名 → 正常加载（验证：单测 + Ink 测试；AC5）
- [x] 指向 skills 目录外的符号链接未被加载；超过 64KB 的 Skill 文件被跳过并告警（验证：单测；AC18。本机无创建文件符号链接的权限，该用例跳过；目录链接（junction）用例通过，并经变异检验确认路径校验生效）
- [x] 三个内部样板全部加载成功、无告警，commit 与 review 为共享模式、test 为独立模式，三者都写了白名单（验证：单测；AC16）

## 两阶段加载

- [x] 第一次模型请求中可见全部 Skill 的名字与说明，看不到任何 SOP 正文；超长说明被截断；没有任何 Skill 时请求中不含目录（验证：单测 + Ink 测试；AC7、N1）
- [x] 模型调用加载工具加载共享 Skill → 工具结果含「已激活」，下一次请求中出现该 SOP（验证：单测 + 集成测试；AC8）
- [x] 模型调用加载工具加载独立 Skill → 工具结果为子对话摘要（验证：单测；AC8）
- [x] 加载工具传入不存在的名字 → 结果列出可用 Skill，不抛异常（验证：单测；AC8、N4）
- [x] 激活带白名单的 Skill 后，加载工具仍在下发的工具列表里；任何权限档位下加载本身都不弹确认（验证：集成测试；AC8、F7）

## 共享模式：钉住与调用

- [x] 激活 A、B 后每次请求都带两段 SOP，顺序为 A、B；再次激活 A 后仍只有一段 A，内容是新参数（验证：单测 + 集成测试；AC9）
- [x] 钉住内容位于系统提示词之后、对话历史之前，不出现在对话历史里；上下文压缩后 SOP 仍在（验证：集成测试；AC9、F8）
- [x] 激活或停用 Skill 前后，系统提示词稳定段与环境段的字节完全相同，缓存标记不变（验证：单测比较请求中系统段内容；AC9、N2）
- [x] `/commit 修复登录超时` → 对话区显示原命令，模型收到触发语，同一次请求已含替换后的 SOP；`/resume` 恢复该会话后显示原命令（验证：Ink 测试；AC10）

## 端到端场景（手工，真实终端 `bun run start`）

- [ ] 场景 1：在项目 `.mewcode/skills/hello.md` 写一个简单 Skill 后启动 → 启动摘要计入项目 1 个；`/help` 出现 `/hello（Skill）`；输入 `/he` 补全列表出现它；`/hello 世界` → 模型按该 SOP 回复且用到了参数
- [ ] 场景 2：工作区有未提交改动时输入 `/commit 修复xx` → 模型先查看状态与 diff，给出提交说明并在提交前征求确认，Bash 调用在默认档弹确认；`/skills` 显示 commit 已激活；`/skills off commit` 后再问一句，模型不再按 commit 流程行事
- [ ] 场景 3：不用斜杠命令，直接说「帮我审查一下没提交的改动」→ 对话区出现 `loadSkill(review)` 工具行，随后模型按 review 的 SOP 审查
- [ ] 场景 4：输入 `/test` → 对话区出现带 `[test]` 前缀的工具行，结束后显示「【Skill test 结果】」；接着问「刚才测试结果怎么样」→ 模型能根据回流的结果回答
- [ ] 场景 5：再输入 `/test`，运行中按 Esc → 显示「【Skill test 未完成】」，之后正常对话不受影响
- [ ] 场景 6：放一个坏 YAML 的 Skill 和一个白名单写了不存在工具的 Skill 后启动 → 两条告警各自写明文件与原因，其他功能正常
- [ ] 场景 7（仅 anthropic provider）：连续对话两轮后激活一个 Skill，下一次请求状态栏「缓存读取」仍大于 0（稳定段缓存未失效）
