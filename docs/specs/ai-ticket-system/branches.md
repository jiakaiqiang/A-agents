# 主流程完成后的深入分支与转型路径

前置成果是 [24 小时计划](plan.md) 的训练主流程，以及 [学生手写任务](../../../../ai-ticket-system/docs/learning-tasks.md) 的本人代码、测试和演示。尚未通过的主流程项目优先补齐，随后再按本文件深入。下面是后续学习建议，不计入已投入 4 小时、剩余 20 小时的本轮预算，也不是完成记录。

## 与最初目标的关系

学生已有五年以上 Vue/TypeScript 经验，希望转向 AI 全栈应用开发，目标城市杭州、苏州、西安，期望杭州/苏州 25K+、西安 18–20K+。这些是用户目标，不是教学或市场结果保证。

转型证据要覆盖：可复现的应用、从 UI 到数据库/模型的请求链路、企业授权、RAG 效果记录、事务与防重、独立排错、部署与恢复。求职定位可表述为“具备五年以上前端经验，能够在 AI 辅助下交付端到端 AI 应用”，随后用实际通过的作品支撑。算法研究、模型训练不在本轮应用工程主线中。

## 后续四周的起步安排

按可投入的有效学习时间执行，验收不足时继续当前项，不按日历强行宣称完成。

1. 第一周：完成 P0 与 P1。选一个后端查询、一处事务/并发和一项权限变化，亲自交付；能从日志追踪到 SQL。
2. 第二周：完成 RAG 基线评估，再选择切片、混合检索或重排中的一项有依据的改进。保留改进前后的相同问题集。
3. 第三周：完善部署、恢复及公司内部小范围试运行。处理一个真实反馈，并记录从复现到验证的过程。
4. 第四周：整理可核验的作品和简历，分析杭州/苏州/西安目标岗位的真实 JD，优先补影响投递的缺口。工具调用/MCP 依据岗位和项目需求继续深入。

继续沿用“学生先写核心实现、AI 负责工程辅助和评审、本人运行正反例”的方式。深度学习新框架和增加更多页面时，优先检查是否能改善当前应用交付能力，避免同时开启全部分支。

## 面试与公司推广的验收

面试演示要能说明：为什么使用这个表关系、JWT 与角色数据怎样取得、RAG 如何避免拿到他企业资料、为什么超时后不会重复建单、通知写入失败为何回滚，以及服务重建后数据在哪里。可用“业务问题 → 技术选择 → 自己负责的核心代码 → 实际结果 → 仍待补”的顺序介绍作品。

公司推广前依据 spec.md 的试运行条件补齐主流程、数据访问、附件、并发/事务、防重、固定样例效果、部署恢复，并收集真实使用反馈。24 小时课程完成本身不替代这些验收；目标薪资和录用以实际岗位评估为准。
