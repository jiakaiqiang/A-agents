| 层次 | 当前采用的技术 | 执行约定 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vue Router、Pinia、Element Plus、Vite | 复用 web；表单和后台页面使用 Element Plus |
| 后端 | Node.js 24.21.0、NestJS 12、默认 Express 适配器、pg、Zod | 复用 api；采用 Controller、Service、依赖注入与业务模块；保持 ESM / NodeNext |

| AI | 第三方模型 API、Embedding API、SSE | 后端适配实际协议，能力和向量维度用真实服务验证 |

本轮确认系统 Node 仍为 20.19.6，项目通过 scripts/setup-node.ps1 启用独立 Node 24.21.0 / npm 11.19.0。准确依赖版本以实际项目 package-lock.json 为准，数据库镜像沿用 compose.yaml 中已固定的 pgvector/pgvector:pg16 digest。

官方参考：[NestJS](https://docs.nestjs.com/first-steps)、[Vue](https://vuejs.org/guide/quick-start.html)、[Element Plus](https://element-plus.org/en-US/guide/quickstart.html)、[pg](https://node-postgres.com/features/queries)。这些链接用于查语法，本计划的项目版本以本地锁文件为准。

现有目录职责：web 保存 Vue 应用，api 保存 NestJS 服务，db/init 仅启用 vector；2A 已新增 db/migrations、db/seed 及迁移执行器。fixtures、evals 和 docs 分别保存虚构样例、评估数据与执行记录。Compose 位于工单项目根目录。

## 每张任务卡的执行方法

1. 先说明要实现的功能、给谁使用、何时触发、完成后的表现，以及已有能力与学生本次改动，再给出导师实现、学生手写、输入输出、正反例及预算。复用已确认设计；未决业务问题一次询问一项。
2. 导师完成框架、依赖、迁移、重复接口/页面和测试工具；学生任务以函数签名、数据结构和调用位置交付，核心实现保留 TODO。
3. 学生先写第一版，允许查资料和请求提示；导师先讲不同业务的小例子，再评审本题并解释错误。没有学生尝试时不提前填完整答案；示范后再做变化题，并登记帮助程度。
4. 学生代码接入真实调用链，亲自验证正例与反例并解释。导师负责工程集成评审和必要回归；缺少核心代码或学生验证时不能宣布该能力已掌握。
5. 工程与学生验收分别勾选，记录本人改动、命令、实际结果和提示使用情况。复盘必须演示自助解决、转人工到知识回流两条闭环。
6. 阶段超时先缩小页面和配置 CRUD，保留真实 AI、企业授权、事务、学生核心实践和最后一小时。未通过项继续待办。

后续每次教学以 [详细分工与手写任务](../../../../ai-ticket-system/docs/learning-tasks.md) 为依据；新会话继续课程也先读取该文件。下面的学生函数不能由导师在生成整个模块时一并代写。24 小时后再进入 [深入分支与转型路径](branches.md)。

实际交接按 [course-workflow.md](../../../../ai-ticket-system/docs/course-workflow.md)。当前任务 S3-B，最新状态以 [current-progress.md](../../../../ai-ticket-system/docs/current-progress.md) 与 [status.md](../../../../ai-ticket-system/docs/tasks/status.md) 为准。任务预算总量不变，用户未提供新的有效学习总时间。
