# 斜杠命令系统 Spec

## 背景
MewCode 现有的斜杠命令（/resume、/exit、/compact、/plan、/do、/accept-edits、/bypass）以条件分支硬编码在回车处理里：
没有统一元数据、没有 /help 与补全；新增命令要改界面层，命令逻辑与渲染框架耦合；拼错的命令会被当作普通消息发给模型，白白消耗 Token。
状态栏目前以中文标签（计划 / 默认 / 接受编辑 / 放行）显示权限档位。

## 目标
- 斜杠开头的输入绕过 Agent，本地确定性执行，响应快、不耗 Token。
- 一个注册中心统一管理命令元数据，命名冲突在启动期暴露。
- 命令实现不绑定具体渲染框架，可独立测试。
- 提供实时补全提示，降低记忆成本。
- 原有 7 个命令行为不变地迁入新机制。

## 功能需求

- F1: 命令定义
  每条命令登记：名称、别名列表（可空）、简短描述、用法示例、命令类型（本地 / 影响界面 / 提示词）、运行中是否可用；
  可选：参数提示、是否隐藏、执行逻辑。本地与界面类必须有执行逻辑，提示词类必须有提示词模板。
  名称与别名只允许小写字母、数字、连字符。

- F2: 注册与冲突检测
  启动时一次性注册全部内置命令。名称/别名之间任意重复（不区分大小写）、名称非法、缺执行逻辑或模板，均使启动失败：
  输出指明冲突双方的错误信息，以非零退出码退出，不进入界面。

- F3: 解析
  输入去首尾空白后为空则直接返回、不做任何事。首字符为 / 即命令输入：斜杠后到第一个空白字符（含换行）前为命令名，转小写；
  其余部分去首尾空白为参数原文（可空）。命令名为空或未命中时，显示「未知命令：/xxx，输入 /help 查看可用命令」，
  不发给模型、不写入对话历史。

- F4: 回车分流
  回车提交先经分流器：命令输入走本地分发，其余照旧送 Agent。命令输入（含未知命令）不触发模型请求。命令输入也记入输入框历史（↑ 可翻出）。

- F5: 三类执行
  本地类：读取状态，以系统消息展示，不改变任何状态。
  影响界面类：修改会话或界面状态（档位、历史、当前会话等），以系统消息或状态栏反馈。
  提示词类：模板展开成一条用户消息，末尾追加参数，走与普通消息相同的 Agent 流程；对话区显示用户输入的原命令，模型收到展开后的文本。
  会话存档同时保留原命令，/resume 恢复后对话区仍显示原命令，模型历史仍是展开文本。
  命令执行出错时显示错误消息，会话保持可用。

- F6: 运行中可用性
  Agent 运行中输入不允许运行中执行的命令，显示「Agent 运行中，请稍后或按 Esc 中断」，不执行。压缩、恢复等维护进行中保持现有的输入框禁用。

- F7: 参数校验
  不接受参数的命令收到参数时，显示该命令用法，不执行。本期仅 /help 与 /review 接受参数。

- F8: 界面控制接口
  命令只通过一组界面能力操作界面，不直接依赖渲染框架。至少包括：显示系统消息（普通/错误）、发送用户消息、切换权限档位、
  查询 Token 用量与上下文占用、刷新状态栏；另为迁入的旧命令提供：清空对话并开新会话、手动压缩、打开会话恢复列表、退出程序；
  以及只读的状态快照（provider、会话、记忆、权限规则、MCP 连接）。

- F9: 状态栏模式标记
  状态栏左侧显示 [PLAN] / [DEFAULT] / [ACCEPT-EDITS] / [BYPASS]。命令或 Shift+Tab 切档后立即更新。

- F10: 实时补全提示
  输入框为单行、以 / 开头、尚未出现空白字符时，下方实时列出匹配命令：名称与别名按前缀匹配（不区分大小写），隐藏命令不参与，
  按主名字母序排列，每项显示主名与描述。只输入 / 时列出全部非隐藏命令；无匹配时不显示列表。
  列表可见时：↑↓ 移动高亮（到头停住）；Tab 填入「/主名 」并收起（单匹配同样直接补全）；Enter 执行高亮命令；
  Esc 只收起列表、保留输入，不中断 Agent。继续输入时列表随之刷新。列表不可见时 ↑↓ 照旧翻历史。

- F11: 别名
  别名与主名完全等价，可用于执行和补全；按别名匹配时补全填入主名。/help 显示每条命令的别名。

- F12: 内置命令（14 个）

  | 命令 | 别名 | 类型 | 运行中 | 参数 | 行为 |
  |---|---|---|---|---|---|
  | /help | h | 本地 | ✓ | [命令名] | 无参列出全部非隐藏命令（主名、别名、描述）；带参显示该命令用法、别名、参数提示 |

## 非功能需求
- N1: 本地与界面类命令不发起网络请求，回车后立即反馈；补全匹配在每次按键时同步完成，无可感知延迟。
- N2: 注册、解析、分发与全部命令实现不依赖终端渲染框架，可用假的界面控制实现单独做单元测试。
- N3: 原有 7 个命令的可观测行为不变；Shift+Tab 切档、Esc 中断、确认框按键等现有交互不受影响；现有测试全部继续通过。
- N4: 命令执行抛出的异常在分发层兜住并转为错误消息，界面不崩，会话可继续。
- N5: 只读命令的输出不出现密钥、令牌等敏感配置；provider 只显示名称、协议、模型与端点主机名（不显示完整 URL）。
- N6: 命名冲突在注册阶段暴露，不等到用户输入某命令时才报。
- N7: 新增一个内置命令只需新增一条定义并登记，不改解析器、分发器或界面层。

## 不做的事
- 用户自定义命令（从配置或目录加载）——留给 Skill 系统。
- 动态生成提示词（模板变量、按上下文拼接）；/review 只追加参数原文。
- 命令级权限控制。
- 以 / 开头的普通消息转义发送给模型（本期 / 开头一律按命令处理）。
- 参数补全（只补全命令名）；模糊匹配（只做前缀）。
- /memory、/permission 的写操作（删记忆、增删规则、/permission <档位>）及 /session 子命令。
- 输入历史跨进程持久化。

## 验收标准
- AC1 (F1, F2): 登记一条名称含大写或空格、或提示词类缺模板的命令 → 启动失败，错误信息指明该命令。
- AC2 (F2, N6): 两条命令名称/别名重复（含大小写不同）→ 启动输出含双方名称的错误，退出码非零，不进入界面。
- AC3 (F2, F12): 14 个内置命令正常注册，启动无冲突。
- AC4 (F3): /HELP 与 /help 输出一致；`/help   status ` 解析出命令 help、参数 status。
- AC5 (F3, F4): 输入 /foo → 显示含 /help 引导的未知命令提示；模型请求次数为 0，对话历史条数不变。
- AC6 (F3): 只含空白的输入不产生任何消息或请求。
- AC7 (F4): 普通文本照常送 Agent；任意已知命令执行后模型请求次数为 0（/review 除外）；命令出现在 ↑ 历史中。
- AC8 (F5): 本地类命令执行前后对话历史、档位、会话 ID 均不变。
- AC9 (F5, F12): 输入 `/review src/tui` → 对话区显示原命令，模型收到的用户消息含模板内容与「审查范围：src/tui」；/resume 恢复该会话后对话区显示 `/review src/tui` 而非展开全文，恢复后续问时模型历史中仍是展开文本。
- AC10 (F5, N4): 命令执行逻辑抛错 → 显示错误消息，之后发送普通消息仍能正常对话。
- AC11 (F6): Agent 运行中输入 /clear、/compact、/review → 显示运行中提示且不执行；输入 /status、/plan → 正常执行。
- AC12 (F7): `/status foo` → 显示 /status 用法，不执行。
- AC13 (F8, N2): 用假的界面控制实现可在不启动终端界面的情况下测试全部 14 个命令。
- AC14 (F9): /plan 后状态栏显示 [PLAN]；Shift+Tab 循环四档时标记依次对应变化。
- AC15 (F10): 输入 / 列出全部非隐藏命令；/s 列出 /session、/status；/zz 无列表；隐藏命令不出现；出现空格后列表消失。
- AC16 (F10): 列表可见时 ↓ 移动高亮、Tab 填入「/status 」、Enter 执行高亮项、Esc 收起并保留输入且 Agent 不被中断；列表不可见时 ↑ 翻历史。
- AC17 (F11): /q、/quit 与 /exit 等价；输入 /qu 时列表显示 /exit，Tab 填入「/exit 」；/help 输出含别名。
- AC18 (F12): /clear 后对话区与历史为空、会话 ID 改变、旧会话出现在 /resume 列表、档位不变；/memory 无条目时显示「暂无记忆」；/session、/permission、/status 输出包含表中字段。
- AC19 (N3): 原 7 个命令行为不变，全量测试与类型检查通过。
- AC20 (N5): /status 输出不含配置中的密钥值，端点只显示主机名。
