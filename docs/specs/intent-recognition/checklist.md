# 意图联合识别模块 Checklist

> 每一项通过运行代码或观察行为来验证,聚焦系统行为。
> 本模块为纯输入输出单元,除「真实端点手工验收」一节外,其余均可在不跑通
> 主对话链路的前提下验证。

## 行为(AC 逐条)

- [ ] AC1 配置缺字段/端点非法 → 启动期清晰错误 + 非零退出;密钥回退生效;
      任何界面区域无密钥
- [ ] AC2 一次识别调用发生在主请求之前,五项字段齐全
- [ ] AC3 显式危险样本(删除目录 / 清空数据库 / rm -rf / 覆盖配置)
      → dangerous 均为 true,原因指向具体对象
- [ ] AC4 温和危险样本("清理一下没用的文件" / "恢复初始状态" /
      "这个模块不要了")→ dangerous 均为 true
- [ ] AC5 非危险样本(解释函数 / 加字段 / 查调用)→ dangerous 均为 false
- [ ] AC6 非 JSON / 缺字段 / 类型错 / 非法类别 → 降级;含未注册工具名 →
      剔除后继续
- [ ] AC7 识别目标八字段齐全且类型正确
- [ ] AC8 不可达 / 超时 / 结构不符 → 降级目标形状正确,注明原因
- [ ] AC9 识别目标被完整交出给调用方(结构体断言可见)
- [ ] AC10 危险 / 非危险 / 降级三种摘要样式可区分,含耗时数值
- [ ] AC11 识别 token 与主对话 token 分别可见
- [ ] AC12 关闭识别后无调用、无摘要行
- [ ] AC13 桩延迟 2000ms 时在阈值处降级,耗时增量 ≤ 阈值 + 100ms
- [ ] AC14 识别期间中断 → 抛 AbortError,可继续下一轮
- [ ] AC15 端点全程不可达时连续三轮均以降级目标正常完成

## 不变式(每条退出路径各验一次)

- [ ] 正常路径:`degraded === false` 且 `degradeReason === ""`
- [ ] 降级路径:`degraded === true` 且 `dangerous === true` 且
      `allowedTools` 等于只读子集
- [ ] 任意路径:`dangerous === false` 时 `dangerReason === ""`;
      `dangerous === true` 时 `dangerReason` 非空
- [ ] 任意路径:`allowedTools` 中每一项都在已注册工具清单内
- [ ] 任意路径:`elapsedMs > 0`(含降级与关闭)
- [ ] 中断路径:抛 AbortError,不返回降级目标

## 回归

- [ ] 既有全部单测仍通过,无跳过用例
- [ ] `bun run typecheck` 退出码 0
- [ ] 未配置 recognizer 节时,现有对话流程行为不变
- [ ] 未引入新第三方依赖(`package.json` 未改动)

## 真实端点手工验收

- [ ] 用 T8 导出的三组样本逐条打真实识别端点,记录 dangerous 实际值,
      统计漏报(AC3/AC4 组出现 false)与误报(AC5 组出现 true)条数
- [ ] 漏报条数为 0;若非 0,记录具体样本并调整 F3 提示词后重跑
- [ ] 记录单次识别真实耗时区间,与超时阈值 1500ms 对比,判断阈值是否需要调整
- [ ] 记录识别调用的实际 token 消耗,评估每轮成本增量
