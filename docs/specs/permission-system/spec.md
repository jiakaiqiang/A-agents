# 权限系统 Spec

## 背景

MewCode 目前对工具调用没有任何准入控制：模型给出的调用只要参数合法就会执行。现状里已有的安全能力只有两处——文件类工具的路径解析会把路径限制在工作目录内（先解析符号链接再做前缀判断），以及系统提示词里的一段口头约定「破坏性操作先确认」。前者覆盖不到 Bash：命令字符串完全不被检查，`cat /etc/passwd`、`cd .. && rm -rf x` 都会直接跑。后者只是提示词，模型可以不遵守，没有任何机制兜底。

配置系统已经具备用户级、项目级、项目本地级三层文件的级联合并能力，并且已经声明并合并了一个表示权限档位的配置字段，但全项目没有任何代码读取它。

这一章给 MewCode 装上五层防御的权限系统，把上面这些零散能力收进一个统一的准入判定里。

## 目标

- 所有工具调用在真正执行前必经一次权限判定，不存在绕过路径。
- 已知高危命令由不可配置放开的黑名单硬拦。
- 文件操作与 Bash 命令中出现的路径都被限制在项目目录内。
- 用户能用「工具名(模式)」声明放行与拦截，按三层配置文件加会话级临时规则逐层生效。
- 用户能整体切换四档权限模式，作为规则未命中时的批量兜底。
- 规则未命中且档位要求确认时，把决定权交回用户，支持本次、本会话、永久三种放行。
- 权限拒绝不终止 Agent Loop，以工具失败结果的形式回给模型，让模型有机会调整策略。

## 功能需求

### 统一判定

- **F1**：所有工具调用在参数校验通过之后、工具真正执行之前，必经一次权限判定。判定结果只有放行与拒绝两种，没有第三种状态。判定对所有工具一视同仁，不存在跳过判定的工具。
- **F2**：判定按五层顺序进行——黑名单、路径沙箱、规则引擎、权限档位兜底、人在回路。每一层给出三种表态之一：拒绝、放行、不表态。拒绝与放行都立即终止判定并短路返回，不再进入后续层；不表态才继续进入下一层。黑名单与路径沙箱只会给出拒绝或不表态，不具备放行能力，因此通过这两层不等于获得放行；人在回路是最后一层，必然给出拒绝或放行，不会不表态。
- **F3**：权限拒绝以工具失败结果的形式回给模型，不终止 Agent Loop，不新增循环终止原因。失败结果中说明是哪一层拒的以及原因，模型可据此调整策略后重试其他方案。

### 第一层：危险操作黑名单

- **F4**：用正则模式集合匹配 Bash 命令文本，命中即拒绝。
- **F5**：黑名单不可被任何配置、任何权限档位、任何规则放开。放行档也不例外，用户写下的 allow 规则同样救不回被黑名单拦下的命令。

### 第二层：路径沙箱

- **F6**：文件类工具（读取、写入、编辑、文件名匹配、内容搜索）的目标路径必须落在项目工作目录内。判定方式是先解析符号链接得到真实路径，再做前缀判断，防止通过链接逃逸。目标文件尚不存在时（如新建写入），向上取到最近的已存在祖先目录解析，再拼回缺失片段。
- **F7**：Bash 命令的路径约束在命令字符串的文本层完成：识别出明确的绝对路径片段与包含 `..` 的相对路径片段，逐个按 F6 的规则判定，任一片段出界即拒绝整条命令。只做文本识别，不展开变量、不求值、不模拟 shell 解析。
- **F8**：路径沙箱与黑名单同级，不可被任何配置或权限档位放开。

### 第三层：可配置规则

- **F9**：规则写成「工具名(模式)」的形式。模式对该工具的关键参数做匹配，支持精确匹配与 glob 匹配两种。
- **F10**：Bash 规则的匹配对象是整条命令字符串，不按 `&&`、`|`、`;` 等分隔符拆分成子命令分别判定。
- **F11**：每条规则的结果只有 allow 与 deny 两种。
- **F12**：规则按四层来源生效，优先级从高到低为：会话级临时规则、项目本地级配置、项目级配置、用户级配置。逐层判断，高优先级层命中即定，不再查看更低层。
- **F13**：同一层内 allow 与 deny 同时命中一个调用时，该层配置中书写顺序靠后的那条生效。因此同一层的规则必须是一个保序的规则列表，而不是按 allow 与 deny 分成两个无序集合。

### 第四层：权限档位

- **F14**：提供四档权限模式，各档在规则未命中时的兜底语义如下：

  | 档位 | 切换命令 | 读类工具 | 写类工具 | Bash |
  |---|---|---|---|---|
  | 计划 | `/plan` | 放行 | 确认 | 确认 |
  | 默认 | `/do` | 放行 | 确认 | 确认 |
  | acceptEdits | `/accept-edits` | 放行 | 放行 | 确认 |
  | 放行 | `/bypass` | 放行 | 放行 | 放行 |

  读类工具指无副作用的工具，写类工具指会修改文件的工具。
- **F15**：权限档位只在规则引擎未命中时生效。任何已命中的 allow 或 deny 规则都不被档位覆盖——切到放行档不能盖掉用户写下的 deny，切到计划档也不会让用户写下的 allow 变成需要确认。档位的作用是对未被规则覆盖的调用做批量处理。
- **F16**：四档通过四个独立命令在运行时切换，切换立即对后续调用生效，不影响正在执行中的调用。
- **F17**：启动档位取自配置中的权限档位字段。字段缺失时用默认档；字段值不是四档之一时按默认档处理并向用户提示该值无效。
- **F18**：计划档与默认档的权限语义完全相同，两者的差别只在系统提示词：计划档保留现有的计划模式提醒——在用户明确批准之前不修改文件、先把情况调研清楚并产出方案。
- **F19**：计划档下写类工具与 Bash 照常下发给模型，不再做只读工具过滤。计划档对文件修改的约束改由逐次确认承担，而非从工具列表里摘掉。

### 第五层：人在回路

- **F20**：规则未命中且当前档位对该类工具要求确认时，向用户呈现待执行的调用摘要并等待选择。可选项为四项：本次放行、本会话放行、永久放行、拒绝。
- **F21**：本次放行仅对当前这一次调用有效，同一调用下次出现仍会再次询问。
- **F22**：本会话放行在内存中登记为一条会话级临时规则，本次进程内后续同样的调用直接放行，进程退出即失效，不落盘。
- **F23**：永久放行写入项目本地级配置文件，写入内容是当次调用的精确整串，不做泛化推断。
- **F24**：用户选择拒绝时，回给模型的是固定文案，不采集也不转达用户填写的理由。
- **F25**：交互确认只发生在串行执行路径上——需要确认的调用各自单独执行，不与其他调用并发。并发执行的只有读类调用，而读类在四档下一律放行，因此并发路径永远不会触发确认。规则命中 deny 的读类调用直接返回失败结果，不阻塞界面。

## 非功能需求

- **N1**：判定必须在工具产生任何副作用之前完成，不允许「先执行再拦截」或「执行后回滚」。
- **N2**：黑名单与路径沙箱的不可放开性要由代码结构保证——不存在能让它们失效的配置项或档位取值，而不是依赖某个配置的默认值恰好安全。
- **N3**：单次判定只做文本匹配与内存查表，不引入额外的磁盘或网络访问，对单次工具调用的耗时影响可忽略。配置文件读取沿用现有的启动时加载，不在每次判定时重读。
- **N4**：拒绝原因面向模型可读：说明被哪一层拒绝、涉及哪个参数或路径，使模型能判断是该换方案还是该向用户请求授权。
- **N5**：权限配置解析失败或格式非法时，不得静默放开权限，应退到默认档并向用户提示。
- **N6**：项目本地级配置承载个人信任决定，不应进入版本库。
- **N7**：新增的权限行为不得与系统提示词中已有的安全约定冲突（破坏性操作先确认、不擅自执行 git push 与部署发布）。
- **N8**：黑名单模式集合、四档档位名、各类工具的分类归属集中声明，不散落在各处判断里。

## 不做的事

- 网络请求限制、资源配额、审计日志——留给后续章节。
- OS 级真隔离沙箱。当前目标平台（Windows 家庭版）不提供可用的隔离原语：Windows Sandbox 仅限专业版与企业版，AppContainer 与 Job Object 没有可直接调用的接口、需要引入原生扩展，容器方案需要常驻容器运行时并改变路径语义与工具链可用性。这一章的 Bash 约束明确定位为文本层检查，不以沙箱命名，不暗示存在进程隔离。
- glob 之外的规则匹配语法——不做正则规则，不做参数级的细粒度条件表达式。
- 并发批内的交互确认。
- 统一的「查看当前档位」入口，档位只能通过切换命令改变。
- 修复项目配置目录未被版本库忽略的问题。该目录当前整体未被忽略，含真实密钥的配置文件也在版本库内；这是一个独立的问题，不混进这一章处理。

## 已知取舍

以下三条是上面决策的必然代价，接受并记录，不在这一章解决：

- **命令串联可被整串放过**：Bash 规则整串匹配（F10），因此 `Bash(git *)` 这条 allow 会放行 `git status && mv src /tmp`。黑名单（F4）仍能拦住其中列举过的高危片段，但黑名单没覆盖到的破坏性命令会被放过。
- **路径检测存在误报**：文本层识别（F7）无法区分路径与普通字符串，`grep -r ".." .` 这类命令会因为参数里出现 `..` 被拦。
- **永久放行不泛化**：精确整串写入（F23），`npm test` 放行后 `npm test --watch` 仍会再次询问。

## 关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| D1 规则与档位的优先关系 | 规则优先，档位只管规则未命中时的兜底 | 用户显式写下的 deny 是明确意图，档位是批量手段；让批量手段盖掉明确意图会让 deny 变得不可信 |
| D2 Bash 的约束形态 | 黑名单加文本层路径检测，不做 OS 沙箱 | 目标平台无可用隔离原语；把文本检查命名为沙箱会让人以为存在进程隔离，比诚实的文本检查更危险 |
| D3 沙箱的可放开性 | 与黑名单同级，不可放开 | 路径出界的破坏性与高危命令同级，没有理由让它比黑名单更容易被放开 |
| D4 计划档的定位 | 权限与默认档相同，差别在提示词；写类工具照常下发 | 提示词管模型该做什么，权限管什么需要人点头，两者正交；摘掉工具会让模型无法在获批后立即动手 |
| D5 永久放行的落点 | 项目本地级配置 | 信任决定与具体项目相关且属于个人选择，不该进项目共享配置，也不该污染用户全局默认 |
| D6 同层冲突的裁决 | 配置中书写顺序靠后的赢 | 顺序是用户可见可控的，比「deny 恒胜」更能表达「先粗后细」的意图；代价是规则必须存成保序列表 |
| D7 确认的执行路径 | 只走串行路径，不改并发分批逻辑 | 需要确认的工具本就都有副作用、本就各自单独串行执行；并发路径上只有一律放行的读类，天然不会触发确认 |

## 验收标准

- **AC1**（F1、N1）：对任意工具构造一次调用，观察到权限判定在工具执行前发生；判定拒绝时工具没有产生任何副作用。
- **AC2**（F2）：构造一个同时会被黑名单和规则命中的调用，观察到黑名单先给出拒绝且规则未被求值。
- **AC3**（F3）：权限拒绝后 Agent Loop 继续运行，模型收到带原因的失败结果并能发起下一次调用；循环终止原因集合未新增取值。
- **AC4**（F4）：黑名单中列举的高危命令被拒绝执行。
- **AC5**（F5）：在放行档下、且配置了匹配该命令的 allow 规则时，黑名单命令仍被拒绝。
- **AC6**（F6）：工作目录外的绝对路径、通过 `..` 逃逸的相对路径、指向目录外的符号链接，三种情况的文件读写均被拒绝；工作目录内尚不存在的新文件写入被放行。
- **AC7**（F7）：命令 `cat /etc/passwd` 与 `cd ../other && ls` 被拒绝，命令 `npm test` 被放行。
- **AC8**（F8）：在放行档下，工作目录外的文件写入仍被拒绝。
- **AC9**（F9、F11）：配置 `allow: Bash(git *)` 后 `git status` 被放行；配置精确规则时只有完全一致的调用被命中。
- **AC10**（F10）：配置 `allow: Bash(git *)` 后 `git status && mv src /tmp` 被整串放行，与已知取舍一致。
- **AC11**（F12）：同一调用在项目级为 deny、在项目本地级为 allow 时最终放行；在项目本地级为 deny、用户级为 allow 时最终拒绝。
- **AC12**（F13）：同一层内先写 deny 后写 allow 时该调用被放行，两行顺序调换后被拒绝。
- **AC13**（F14）：四档各自对读类、写类、Bash 三类未命中规则的调用给出表中对应的兜底结果。
- **AC14**（F15）：配置一条 deny 规则后切到放行档，该调用仍被拒绝；配置一条 allow 规则后切到计划档，该调用直接放行而不弹确认。
- **AC15**（F16）：执行四个切换命令后，后续调用的兜底行为按新档位生效。
- **AC16**（F17）：配置文件未声明档位时以默认档启动；声明了不在四档内的值时以默认档启动并出现提示。
- **AC17**（F18）：计划档下系统提示词包含计划模式提醒；默认档下不包含。
- **AC18**（F19）：计划档下下发给模型的工具列表包含写类工具与 Bash。
- **AC19**（F20）：未命中规则的写类调用在默认档下呈现确认提示，提示中包含调用摘要与四个可选项。
- **AC20**（F21）：选择本次放行后该调用执行；同一调用再次出现时再次询问。
- **AC21**（F22）：选择本会话放行后同一调用不再询问；重启进程后再次询问，且配置文件未被写入。
- **AC22**（F23）：选择永久放行后项目本地级配置新增一条精确整串的 allow 规则；重启进程后同一调用直接放行。
- **AC23**（F24）：选择拒绝后模型收到固定文案，界面不出现要求用户输入理由的环节。
- **AC24**（F25）：一次响应中包含多个读类调用与一个写类调用时，读类调用并发执行且全程无确认提示，写类调用单独触发确认。
- **AC25**（N4）：路径出界、黑名单命中、规则 deny、用户拒绝四种拒绝，回给模型的原因文案彼此可区分。
- **AC26**（N5）：权限配置写成非法格式时，启动退到默认档并出现提示，没有任何调用因解析失败而被放行。
- **AC27**（N8）：黑名单模式集合、档位名、工具分类均可在单一位置查到全量定义。
